feat(drupal): make targets for showing/writing .installed marker

Follow-up to the structural-checks refactor (commit 308bdd5).
Post-refactor, `.installed` no longer gates any operation — but the
metadata in it (install date proxy, Drupal version, DB endpoint,
secret paths) is genuinely useful when SSH'd in and asking "when was
this installed?" / "which RDS is this pointing at?" / "where are the
secrets stored?"

Two ergonomic targets and a small refactor to keep the marker
content in one place:

## New: scripts/deploy-host/write-install-marker.sh

Extracted the marker-writing logic from install-drupal.sh:626-643
into a standalone script. Called by both:
  - install-drupal.sh (at end of a fresh install)
  - `make create-installed ENV=<env>` (backfill or refresh)

Single source of truth for what the marker contains. Also fixes the
missing `chown www-data` that Kurt had to do by hand after the manual
backfill this session — the shared script now sets ownership too.

Content improvements over the original:
  - `Marker written at:` timestamp (always fresh)
  - `Install date proxy: settings.php mtime` (best available signal
    for backfills; matches the fresh-install timestamp when this
    runs at end-of-install)
  - Explicit note that all lookups are best-effort — 'unknown' if
    any sub-lookup (SSM param, drush status, stat) fails

## New: make show-installed / make create-installed

`show-installed`:
  - Cat the marker if present, print a helpful pointer to
    `create-installed` if not.
  - Deploy-host-only (guarded by /etc/worxco/deploy-host-marker).
  - Read-only, no ENV required if you already have use-env sandbox
    (or whatever) active.

`create-installed ENV=<env>`:
  - Delegates to write-install-marker.sh via sudo.
  - Idempotent — always overwrites, always safe.
  - Preconditions match the shared script (mount, drush,
    settings.php).

Deliberately named per Kurt's phrasing "make create-installed
seems like a good tool to have."
