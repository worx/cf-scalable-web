feat(migrate-host): Phase 3 — HOST_STACK env-var re-targets dispatch

Adds a single HOST_STACK env-var to _ssm-run-deploy-host.sh so the
same dispatch machinery can drive either cf-deploy-host (current
default) or cf-migrate-host (Phase 4 will make this automatic).

Design compromises:

  1. deploy-host and migrate-host expose the instance-ID under
     different CFN output keys (DeployHostInstanceId vs
     MigrateHostInstanceId). Rather than requiring the caller to
     supply both, the script derives INSTANCE_ID_OUTPUT_KEY via a
     case block. One env var in, correct lookup out. Extending to
     a new host type is a single case-arm addition — flagged in
     the comment.

  2. DEPLOY_HOST_STACK is kept as a back-compat alias so anything
     that already sets it (nothing in-tree today, but external
     wrappers might) keeps working. Precedence:
       HOST_STACK > DEPLOY_HOST_STACK > cf-deploy-host default

  3. Unknown HOST_STACK values fail loudly at the case block
     BEFORE we hit AWS APIs — better error than a mysterious
     "stack not found".

No caller changes: every existing dispatch-* Makefile target still
resolves to cf-deploy-host by default, so today's behavior is
byte-identical. To exercise Phase 2's migrate-host tunings in a
real timing test:

  cd migration
  HOST_STACK=cf-migrate-host make dispatch-restore-mysql
  HOST_STACK=cf-migrate-host make dispatch-run-pgloader

Phase 4 (task #30) wraps that into MIGRATE_HOST_LIFECYCLE for
migrate-db-all.

Verified: bash -n clean. Dry-ran the case block against
cf-deploy-host, cf-migrate-host, cf-bogus (rejected), no vars, and
DEPLOY_HOST_STACK-only — all four resolutions correct.
