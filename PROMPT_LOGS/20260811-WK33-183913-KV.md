Drupal is serving PDF page markup with URLs pointing at `s3://sandbox-drupal-media-.../...`, but the objects aren't there yet. Hence 404s at the object level.

**Fix (~ seconds to hours depending on prod media size):**

```bash
cd migration
make sync-s3-media CONFIRMED=yes
cd ..
```

No cache-clear or PHP-FPM restart needed — Drupal generates URLs based on filenames; once the objects exist at those URLs, next request works. Retry a PDF in the browser after sync completes.

**Runtime note:** `sync-s3-media` is `aws s3 sync` between two S3 buckets. Cross-account cross-region metadata + object copy. Time scales with total media size. Small envs finish in a minute; a big media library can take an hour.

If you want to test a single PDF quickly WITHOUT waiting for the full sync: pick one filename that's 404ing, `aws s3 cp` it directly from prod to sandbox, and retry that specific URL. Confirms the fix works before you commit to a long sync.

**After sync completes, your sandbox will fully mirror prod:** DB migrated, codebase restored, public/private files restored, media synced. That's a complete migration.
