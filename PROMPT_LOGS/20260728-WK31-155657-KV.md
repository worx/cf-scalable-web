chore(deploy-host): refresh-deploy-host-scripts — git-pull as ubuntu, not root

The inner script that SSM ships to the deploy-host runs as root by
default. `git pull` as root has no `~/.ssh/known_hosts` and no GitHub
SSH creds, so every invocation prints:

  Host key verification failed.
  fatal: Could not read from remote repository.

...and falls through to the `|| echo "WARN: git pull failed…"` branch.
The `install -m 0755` steps that follow still update the three files
from whatever the ubuntu-user checkout already had on disk, so this is
cosmetic, not blocking. But it's noise in the log every time — the
happy path never runs a real git pull.

## Fix

L62 changes from:

  git -c safe.directory="$REPO" pull --quiet

to:

  su - ubuntu -c "cd '$REPO' && git pull --quiet"

Running as `ubuntu` inherits ubuntu's `~/.ssh/known_hosts` (populated
during initial repo clone in bootstrap.sh) and Git identity. The
`safe.directory` flag is no longer needed since ubuntu owns the repo.

The `|| echo "WARN: ..."` fallback stays in place — real failures
(offline, GitHub creds rotated, upstream branch renamed, etc.) still
degrade gracefully to "reinstall from existing checkout" instead of
aborting the whole refresh.
