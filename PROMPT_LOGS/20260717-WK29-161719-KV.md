### 16:18:00 - Response

Great insight, and it's the right design goal for anything past a demo. Two things:

## The prior art we already have

`migration/scripts/_ssm-run-jumpbox.sh` is exactly the pattern you're describing — for `dump-mysql`, `dump-codebase`, etc. It:

- Kicks off with `aws ssm send-command` (returns immediately, no interactive session)
- Polls `get-command-invocation` for status
- Streams output back through CloudWatch (or via `--output-s3-bucket-name`)
- **Survives ANY Mac-side interruption** — the command lives inside SSM's own runner on the target host, not on our terminal

That's the "kick it off and walk away" model. Doesn't matter if your laptop sleeps, your SSM session times out, or you close the lid — the work continues on the deploy-host and result lands in S3 logs.

## What we'd build for the deploy-host side

Mirror `_ssm-run-jumpbox.sh` → `_ssm-run-deploy-host.sh`, then wrap `restore-mysql` and `run-pgloader` (and any future migration steps) with Mac-side dispatch targets. Rough sketch:

- `make dispatch-restore-mysql` — from Mac, fires SSM send-command with a 30-min execution timeout. Deploy-host runs `restore-mysql.sh`, logs to `s3://…/logs/YYYY-MM-DD/`. Returns command ID immediately.
- `make dispatch-run-pgloader` — same, with a 60-min timeout.
- `make migration-db-status` — poll the last N SSM command invocations against deploy-host, show status of each.
- Optionally: `make dispatch-db-migrate-all` — chained (dispatch restore-mysql → wait for success → dispatch run-pgloader) via SSM send-command's `--wait-until` or a poll loop in the Makefile.

Add this to the follow-ups list. Not for right now — mid-migration is the wrong time to change the tooling.

## Right now

Current pgloader run inside tmux is unaffected by your Session Manager timeout — tmux keeps running as a root-owned session on the deploy-host. To check status:

```bash
# Fresh SSM session
make ssm-deploy-host
sudo tmux ls                              # should show 'pgloader' still attached
sudo tmux attach -t pgloader              # jump back in, see current progress
# ... detach again with Ctrl+B D
```

If tmux `ls` shows no session → pgloader either finished (paste output) or died. Log at `/var/log/worxco-migration/run-pgloader-*.log` will tell either way.
