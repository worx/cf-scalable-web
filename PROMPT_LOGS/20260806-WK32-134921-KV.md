fix(migrate-host): restart mariadb after drop-in + verify buffer pool

Root cause: `apt-get install -y mariadb-server` starts the service
immediately with distro defaults BEFORE bootstrap.sh writes
/etc/mysql/mariadb.conf.d/99-migrate-host.cnf. The subsequent
`systemctl enable --now mariadb` was a no-op on an already-running
service and never picked up the 8G buffer pool + bulk-load flags.

Silent bug — box works, migrations just run against 128 MiB buffer
pool at distro-default speed (defeats the whole point of the beefy
migrate-host).

Fix:
1. Split `enable --now` into `enable` + explicit `restart` — restart
   forces the config reload regardless of current running state.
2. Add a post-restart guard: query @@innodb_buffer_pool_size and
   `exit 1` if under 1 GiB. Future silent regressions fail loudly
   instead of just being slow.

Verified live on i-0abea6f380500ce0d: after `sudo systemctl restart
mariadb`, buffer pool is 8589934592 (8 GiB) as designed.
