feat(salt): migrate Drupal hash_salt from FSx file to Secrets Manager

Closes Option B from the salt-preservation discussion. Salt now lives
at `worxco/${ENV}/drupal/hash-salt` in Secrets Manager, alongside the
existing db-password + admin-password secrets — matches the pattern
Drupal already uses for other per-env secrets, IAM-scoped so cross-env
sharing is impossible, and immune to file-system operations like
restore-private's atomic swap.

## Why we moved

Historical (docs/memory/salt-persistence-design.md): salt.txt on FSx
was destroyed by `make destroy-all`, invalidating all sessions/tokens.
Recent (2026-07-19): restore-private's atomic swap silently loses
salt.txt during migration, WSOD'ing Drupal until operator manually
restores from .BAK.

SSM eliminates both. FSx destroy → salt survives. restore-private
swap → salt not in the target dir at all, nothing to preserve.

## Transition strategy — file kept as fallback until verified

To avoid a big-bang change, this commit implements SSM as primary
with the existing file as fallback:

  install-drupal.sh:
    - Case 1: SSM secret exists → use it. Sync file to match.
    - Case 2: SSM missing but salt.txt exists → migrate file → SSM
              (one-time upgrade for existing sandboxes). File stays.
    - Case 3: Neither exists → generate fresh, write to BOTH.
    Result: existing sandboxes with a file-only salt smoothly upgrade
            on next install-drupal run.

  refresh-env-config:
    - Fetch salt from SSM (empty if secret missing).
    - Export DRUPAL_HASH_SALT to /etc/worxco/envs/<env>.

  settings.php (rewritten by install-drupal.sh):
    - Prefer getenv('DRUPAL_HASH_SALT'). If empty/unset → fall back
      to file_get_contents('/var/www/drupal-private/salt.txt').
    - Backward compat while PHP-FPM instances rebuild env vars.

  configure-php.sh (image-builder):
    - Fetch salt from SSM.
    - Add `env[DRUPAL_HASH_SALT]` to the pool.d/www.conf managed
      block, alongside env[DRUPAL_DB_PASS] etc.
    - Empty tolerated during transition — settings.php's file
      fallback catches it.

  remove-drupal.sh:
    - Salt secret added to the "preserved (intentional)" list so
      operators see it alongside db-password / admin-password.

## Follow-up (separate commit, once transition is verified)
