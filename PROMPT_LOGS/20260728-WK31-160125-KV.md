## Option A — Partial: re-run just dump-codebase + restore-codebase (30-45 min)

Exercises the two scripts we just refactored, on the *current* sandbox. Doesn't touch infrastructure:

```bash

# then inspect the tarball:
```

## Option B — Full: `make destroy-all` → `make deploy-all` → migration (2-3 hours)

The "real" test — proves a green-field sandbox comes up cleanly with tonight's fixes, no manual band-aids.

**Validates:** everything.

- Deletes everything sandbox-side: RDS backups, FSx contents, ElastiCache. Non-recoverable except from S3 dumps
- Real AWS spend during the churn (not big, but real)

1. Option A catches ~80% of the risk (the fresh code paths) without touching production infrastructure

3. If Option A surfaces something, we fix it fresh before Option B — better sequencing
