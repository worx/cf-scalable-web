docs(memory): capture DB rollback pattern (logical rename, not RDS snapshot)

During planning of the DB-only prod→sandbox test migration, Kurt
corrected an over-engineered rollback proposal (`aws rds create-db-snapshot`
+ restore) with the surgical alternative: logical-DB rename at the
engine level. `ALTER DATABASE drupal RENAME TO drupal_backup_<STAMP>`
+ `CREATE DATABASE drupal` gives a metadata-only, sub-second rollback
that keeps the same RDS instance and endpoint. Rollback via `DROP`
+ rename-back is equally cheap.

Captured as a project memory so future planning doesn't reach for
snapshots again by default. Includes the connection-eviction gotcha
(`ALTER DATABASE` requires no active sessions — must
`pg_terminate_backend` first) and calls out the actual failure modes
that DO warrant snapshot-based rollback (WAL corruption, multi-DB
atomicity, engine-version changes).
