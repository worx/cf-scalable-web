## Are the truncation warnings a problem?

**Almost certainly no.** These are pgloader saying "PostgreSQL's identifier limit is 63 chars, this index name is 66 chars, I'm truncating to 63." Two things to know:

1. **Cosmetic.** The index still exists, still functions, still covers the same columns. Drupal's ORM doesn't care about the exact index name — it looks up by table/column definition, not by index name.
2. **Very rare collision risk.** If two indexes originally differed only in their tail (past character 63), they'd truncate to identical names, and the second CREATE would fail. But Drupal-generated names are usually distinctive well before character 63. In the ones you're seeing:
   - `..._langcode__langcode` (66 chars)
   - `..._langcode__langcode` (74 chars)  
   
   Different table prefixes (`idx_18971_...` vs `idx_18958_...`), so their truncated forms are unique. No collision.

**How you'd know if it WAS a problem:** pgloader would emit `ERROR duplicate key` after the WARNING (which it isn't here). And the table would fail to load, showing up in pgloader's final "summary" as a failure.

## What to actually watch on the current run

- `LOG report summary reset` — pgloader starting a phase
- `Migrating from …` / `Migrating into …` — connection made

- Final `LOG report summary summary` — completion, per-table row counts + errors
