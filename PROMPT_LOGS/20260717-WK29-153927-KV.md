fix(deploy-host): install AWS RDS CA bundle in bootstrap.sh (pgloader TLS)

pgloader's TLS layer (cl+ssl, Common Lisp OpenSSL bindings) validates
the RDS server cert against the system trust store regardless of
`--no-ssl-cert-verification` at the CLI. Ubuntu's default CA store does
NOT include the AWS RDS root CAs, so connections from a fresh deploy-host
fail with:

    KABOOM!
    Failed to connect to pgsql ... SSL verify error:
      19 X509_V_ERR_SELF_SIGNED_CERT_IN_CHAIN

The permanent fix is installing AWS's global-bundle.pem into the system
trust store. Once there, every TLS client on the box (openssl, pgloader,
psql, curl, etc.) can validate RDS-issued certificates.

Discovered during Phase 5 of the DB-only test migration (2026-07-17).
Previous successful pgloader runs must have been against a deploy-host
that had the CA already installed via some past manual step that never
made it into bootstrap.

## Followup: existing deploy-host needs manual install

The currently-running deploy-host is bootstrapped with today's older
version (pre-this-commit). Manually run there:

    sudo curl https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem \
         -o /usr/local/share/ca-certificates/rds-ca.crt
    sudo update-ca-certificates

Then re-run `sudo make run-pgloader CONFIRMED=yes`.

Future deploy-host rebuilds pick this up automatically via bootstrap.sh.

       pattern verified working out-of-band
