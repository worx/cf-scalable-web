## Last remaining piece — settings.php

Drupal itself won't call the S3 stream wrapper until `settings.php` on FSx has the `$settings['flysystem']` block. That's the injection script:

```bash
# SSM into deploy-host:
aws --profile ZI-Sandbox ssm start-session --target <deploy-host-id> --region us-east-1
# or if you have a make target: make ssm-deploy-host

# Once in:
cd /home/ubuntu/projects/cf-scalable-web
git pull
sudo bash scripts/deploy-host/inject-flysystem-config.sh
```

Expected output: `Backup: …pre-flysystem-STAMP` then `OK: flysystem block injected …`. The script also runs `php -l` before AND after — so if `settings.php` has any pre-existing quirks, it refuses to touch it, and if the injection somehow breaks it, it auto-rolls back.

After that runs cleanly, the sandbox stack is *capable of* serving prod's PDFs from S3 — but you won't actually SEE any until you run the DB migration (per `zesty-plotting-squid`), because your current sandbox DB has no `s3://…` entries in `file_managed`.
