### 15:06:14 - Response

Great questions — direct-sync unlocks a much simpler workflow. Both are answerable:

## Q1 — Can jumpbox write directly to `sandbox-drupal-media-kv-worxco`?

**Currently: no.** Jumpbox only has cross-account write to `sandbox-migration-kv-worxco` (via the bucket policy at `cf-migration-bucket.yaml:129-150`).

**But it's a small CFN change.** The MediaBucket in `cf-storage-s3.yaml:58` has no bucket policy today. `BlockPublicPolicy: true` blocks POLICIES-GRANTING-PUBLIC — but does NOT block cross-account policies scoped to a specific principal ARN. We can add exactly the same pattern used for the migration bucket:

```yaml
# In cf-storage-s3.yaml, gated on a new parameter (empty by default →
# no policy attached, no behavior change on prod)
Parameters:
  MigrationSourceRoleArnPattern:
    Type: String
    Description: |
      Optional. Full ARN pattern of a cross-account role allowed to
      sync INTO the media bucket. Set on sandbox to enable prod→sandbox
      media migration. Leave empty on prod.
    Default: ''

Conditions:
  EnableMigrationSourceWrite: !Not [!Equals [!Ref MigrationSourceRoleArnPattern, '']]

Resources:
  MediaBucketPolicy:
    Type: AWS::S3::BucketPolicy
    Condition: EnableMigrationSourceWrite
    Properties:
      Bucket: !Ref MediaBucket
      PolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Sid: AllowMigrationJumpboxSync
            Effect: Allow
            Principal: {AWS: !Sub 'arn:aws:iam::${ProdAccountId}:root'}
            Action: [s3:PutObject, s3:PutObjectAcl, s3:ListBucket, s3:GetObject, s3:DeleteObject]
            Resource: [!GetAtt MediaBucket.Arn, !Sub '${MediaBucket.Arn}/*']
            Condition:
              StringLike:
                'aws:PrincipalArn': !Ref MigrationSourceRoleArnPattern
```

**Cost**: one CFN template edit + one `make deploy-storage-s3 ENV=sandbox` to apply. Prod's stack stays untouched (parameter default is empty).

**Result**: single `make sync-s3-media` — one target, one direction, incremental. Consolidated dump+restore.

Recommend this. Cleaner ops.
