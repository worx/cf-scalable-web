## The relative-path logic

**React2 layout:**
```
/var/www/html/                         ← "one level up from Drupal"
├── zoning_info_platform/              ← Drupal root (contains composer.json)
├── entity_bundle_manager/             ← composer sees this as ../entity_bundle_manager
└── filtered_entity_reference/         ← composer sees this as ../filtered_entity_reference
```

**Sandbox layout (after our extract):**
```
/var/www/                              ← "one level up from Drupal" (this happens to also be FSx root)
├── drupal/                            ← Drupal root (contains composer.json)
├── entity_bundle_manager/             ← composer sees this as ../entity_bundle_manager
└── filtered_entity_reference/         ← composer sees this as ../filtered_entity_reference
```

The name of the parent directory is different (`/var/www/html/` vs `/var/www/`), and the name of the Drupal-root subfolder is different (`zoning_info_platform` vs `drupal`), but the **relative path from composer.json to the two modules is identical**: `../entity_bundle_manager` in both cases.

## The tar command handles the path collapse

Look at what my tar command does:

```bash
tar czf /tmp/custom-modules.tgz -C /var/www/html \
  entity_bundle_manager filtered_entity_reference
```

The `-C /var/www/html` tells tar to `cd` there before archiving. So `entity_bundle_manager` in the archive is stored as bare `entity_bundle_manager/…`, **not** as `html/entity_bundle_manager/…`. No `html/` prefix inside the tarball.

Then when we extract with:
```bash
sudo tar xzf /tmp/custom-modules.tgz -C /var/www/
```

The bare `entity_bundle_manager/…` inside the tarball lands at `/var/www/entity_bundle_manager/…` on sandbox. Which is where composer expects it.

## Verify before extracting (paranoia — good habit)

Right before the extract on deploy-host, we can peek at the tarball to confirm the paths are what we expect:

```bash
tar tzf /tmp/custom-modules.tgz | head -5
```

Expected first few lines:
```
entity_bundle_manager/
entity_bundle_manager/composer.json
entity_bundle_manager/src/
…
```

If you see `html/entity_bundle_manager/` or `zoning_info_platform/...` in the listing, the tar was made differently and we adjust the extract. But given the tar command I gave with `-C /var/www/html`, expected output is the "bare" layout.
