     current-env to the backup to eliminate.

## Fix

After the auto-restore block, retry bootstrap's remount logic:

  if [ -r /etc/worxco/current-env ]; then
    RESTORED_ENV=$(< /etc/worxco/current-env)
    if [ -n "$RESTORED_ENV" ] && [ "$RESTORED_ENV" != "NONE" ]; then
      /usr/local/sbin/use-env "$RESTORED_ENV" || echo "WARN: ..."
    fi
  fi

Guards on file presence, non-empty non-NONE value, and `use-env`
binary being present (bootstrap.sh installs it at line 486, so if
bootstrap ran to completion it's there — but the guard keeps us
from booting with `set -e` on a partial bootstrap).
