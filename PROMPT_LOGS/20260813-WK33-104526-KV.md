### 10:46:16 - Response

Yes on all counts, but slightly more specific:

**drush is project-local** — installed by `install-drupal.sh` via `composer require drush/drush` inside `/var/www/drupal`. It lives at **`/var/www/drupal/vendor/bin/drush`**, not in any PATH. You either cd first + use relative `vendor/bin/drush`, or use `--root=/var/www/drupal`.

**settings.php reads DB credentials from environment variables**, not hardcoded values. So drush also needs `DRUPAL_DB_HOST`/`DRUPAL_DB_USER`/`DRUPAL_DB_PASS`/`DRUPAL_DB_NAME` exported to its process — otherwise it can't connect to RDS.

**Copy-paste ready** for `dblog.settings`:

```bash
sudo bash -c 'source /etc/worxco/envs/sandbox && cd /var/www/drupal && vendor/bin/drush cget dblog.settings'
```

That handles all three requirements at once: sudo (read access to /var/www/drupal), source of env-file (DRUPAL_DB_* vars), cd (drush finds the Drupal root).

Expected output — a YAML dump of the dblog config:
```yaml
row_limit: 1000
```

If `row_limit` is 1000 (default), `dblog_cron()` trims watchdog to the most recent 1000 rows every cron run. If it's 0, unlimited (grows forever).

**Bonus drush commands you might want** (same wrapper pattern):

```bash
# Recent watchdog entries (nicer than raw SQL):
sudo bash -c 'source /etc/worxco/envs/sandbox && cd /var/www/drupal && vendor/bin/drush ws --count=10'

# Filter by type:
sudo bash -c 'source /etc/worxco/envs/sandbox && cd /var/www/drupal && vendor/bin/drush ws --type=php --count=5'

# Delete all watchdog rows (fresh start):
sudo bash -c 'source /etc/worxco/envs/sandbox && cd /var/www/drupal && vendor/bin/drush ws --delete=all'

# Site status (Drupal version, DB connection, module count, etc.):
sudo bash -c 'source /etc/worxco/envs/sandbox && cd /var/www/drupal && vendor/bin/drush status'
```

If you find yourself running these often, a 3-line wrapper script at `/usr/local/bin/drush-env` would make it a one-word invocation. Similar pattern to `psql-env`. Say the word if you want me to write it.
