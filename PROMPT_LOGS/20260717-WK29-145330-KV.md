## Note on the 54 `public` tables

Probably vestigial from an earlier `install-drupal` / `drush site:install` before the `'schema' => 'zinew'` migration. Drupal currently reads from `zinew` per settings.php, so those `public` tables aren't in the serving path — they're orphans.

**Impact on the plan:** none, because Phase 1's rename preserves BOTH schemas in `drupal_backup_$STAMP`. The fresh `drupal` DB will have zero user tables in `public` (only what pgloader creates in `zinew`). If it turns out Drupal actually reaches into `public` for something we haven't traced, rollback puts them back in <1 min.

    WHERE datname = 'drupal' AND pid <> pg_backend_pid();

psql-env sandbox -d postgres -c "GRANT CONNECT ON DATABASE drupal TO drupal_user;"
psql-env sandbox -d postgres -c "GRANT CONNECT ON DATABASE $BACKUP_DB TO drupal_user;"
