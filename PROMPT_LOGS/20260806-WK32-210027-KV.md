**Message:**
```
refactor(dns): move DNS + ALB warm-up from install-drupal → publish-dns

Kurt observation during Phase 3 end-to-end test: the warm-up curl in
install-drupal.sh fires BEFORE publish-dns runs (install-drupal is
step 1 of install-drupal-full; publish-dns is step 3). So the "warm-
up" was warming stale-or-NXDOMAIN state against the OLD DNS entry,
not the fresh alias publish-dns was about to write. Waste of a curl.

Fix: warm-up moves to end of publish-dns.sh, executed immediately
after the Route 53 change is confirmed INSYNC. This is the natural
home:
  - Runs on THIS machine, so it warms this machine's OS resolver
  - Fires AGAINST the just-written record (via authoritative Route 53)
  - Any downstream tooling on same host (smoke-test-public, browser)
    hits primed caches instead of paying first-lookup latency

Design details:
  - HTTP code is INFORMATIONAL, not a pass/fail:
      200 → post-migration, Drupal serving migrated content
      302 → pre-migration, expected (Drupal redirects to install.php
            because schema `zinew` is empty until pgloader runs)
      000/curl-error → DNS still propagating (non-fatal, resolver
                       still got flushed + primed)
      other → any other status, printed for the operator's eyeball
  - `|| true` throughout — warm-up never fails the target
  - Also fixes the propagation-verify branch: previously the success
    branch had `exit 0` inside the loop, so the WARN branch never
    ran the warm-up. Now both branches fall through to a single
    exit path with warm-up. Behavior on WARN unchanged (still exits
    0 — submission-succeeded is authoritative even if propagation
    is slow).

Correcting a small mental-model detail from Kurt's proposal: a warm-
up curl doesn't SHORTEN remote resolver TTLs — remote caches expire
on THEIR own clock, independent of when we curl. But it DOES warm
this machine's local cache and validate the record resolves end-to-
end, which is the real value.

Follow-up task #34 (install-drupal-full ordering — smoke-test fails
on cold-start pre-migration) is unaffected by this change.

Files Modified:
- scripts/publish-dns.sh          (added warm-up section at exit path)
- scripts/deploy-host/install-drupal.sh (removed warm-up step)

Verified: bash -n clean on both.

Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>
```
