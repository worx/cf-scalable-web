Cause: git 2.35+ refuses to operate on repos whose directory owner is

Ironic silver lining: caught only because the previous commit added

## Fix — two layers

**A. Immediate: inline safe.directory in the git command.**

`scripts/dispatch-db-backup.sh` now runs:

    git -c safe.directory=/home/ubuntu/projects/cf-scalable-web pull --quiet \
      || echo "WARN: git pull failed — using existing checkout"

- `-c safe.directory=...` is the one-shot whitelist (equivalent to a
  global git config entry but scoped to this call).
- Best-effort: if the pull fails for any reason (network, merge
  conflict, whatever), we continue with whatever's on disk rather
  than blocking the whole dispatch chain.

**B. Permanent: bootstrap.sh adds safe.directory globally for root.**

New bootstrap step (right after the RDS CA bundle install) runs:

    git config --global --add safe.directory /home/ubuntu/projects/cf-scalable-web

so ANY future root git operation on that repo works without per-command
config. Fresh deploy-hosts pick this up automatically; the running
deploy-host needs the operator to either re-run bootstrap.sh or run the
git config command once manually.

## For the operator

Right now on the running deploy-host:

    make ssm-deploy-host
    sudo git config --global --add safe.directory \
      /home/ubuntu/projects/cf-scalable-web
    exit

Then `make migrate-full-all` retries cleanly. Alternatively, since the
inline fix in dispatch-db-backup.sh above works without the global
config, JUST pulling the latest git on Mac + rerunning
migrate-full-all also fixes it — the inline `-c safe.directory` in
the fresh script side-steps the ownership check without needing
the deploy-host's config.
