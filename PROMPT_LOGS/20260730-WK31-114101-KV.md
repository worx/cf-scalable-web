fix(install-drupal): resolve SCRIPT_DIR before any cd

Bug caught 2026-07-30 during the FIRST successful Phase -1 run
(sudo -E fix from a1a85bc worked). Install-drupal.sh got through
composer install, drush site:install, settings.php write, permissions,
Update module uninstall, drupal.conf vhost publish, and drush verify.
Then failed on the very last step:

    scripts/deploy-host/install-drupal.sh: line 717: ./write-install-marker.sh: No such file or directory
    make[2]: *** [Makefile:1039: install-drupal] Error 127

## Cause

Line 717 was invoking a sibling script via:

    "$(dirname "$(readlink -f "$0")")/write-install-marker.sh" "$ENV"

Which is CORRECT if cwd is where "$0" is invocable relative to.
Problem: install-drupal.sh does `cd $DRUPAL_ROOT` earlier (for drush
site:install and subsequent drush calls) and never cds back. By line
717, cwd is /var/www/drupal/. "$0" is the RELATIVE path given at
invocation (`scripts/deploy-host/install-drupal.sh`), and there's
no scripts/deploy-host/ subdirectory inside /var/www/drupal/. So
`readlink -f "$0"` returns empty. Then `dirname ""` returns `.`.
Result: `./write-install-marker.sh` → 127 (file not found in cwd).

## Fix

Capture SCRIPT_DIR at the top of the file (before any cd) using
${BASH_SOURCE[0]} — the always-correct bash-idiomatic pattern:

    SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

Then reference sibling scripts as "$SCRIPT_DIR/…". Immune to any
future cd's in the script.

Added an explanatory comment block above the SCRIPT_DIR line
documenting the exact bug this pattern avoids, so it doesn't get
"cleaned up" back to the broken form by future refactoring.

## What happened to sandbox

install-drupal.sh completed almost all its work before line 717
failed. State on FSx:
- /var/www/drupal/ — full composer install + drush-installed DB
  tables in RDS + written settings.php + published vhost + working
  drush verify
- /var/www/drupal-private/salt.txt — written with correct ownership
- .installed marker — NOT written (line 717 was going to do that)

Recovery on the botched sandbox for next migrate-full-all run:
    make remove-drupal ENV=sandbox
    git pull
    cd migration
    make migrate-full-all AUTO=yes

Or if operator wants to save time: skip remove-drupal, just re-run
migrate-full-all with SKIP_PREFLIGHT=yes and manually write the
install marker via `make create-installed ENV=sandbox` (which uses
the same write-install-marker.sh via an absolute path).

## Files Modified

- scripts/deploy-host/install-drupal.sh — capture SCRIPT_DIR at top,
  use it at line 734 (was 717) for the write-install-marker call

Tests: bash -n clean.
