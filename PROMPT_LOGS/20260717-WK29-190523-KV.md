docs(deploy-host): document why .installed is NOT in BACKUP_PATHS

Follow-up #3 second-half started as "add /var/www/drupal/.installed
to the deploy-host state backup" but the analysis of what actually
happens on instance replacement showed that's the WRONG call:

  /var/www/drupal/.installed lives on FSx (network-attached, durable
  across deploy-host lifecycle). Every future deploy-host that
  `use-env sandbox`s will see the same marker file already there.

  Additionally, restore-state.sh runs during UserData BEFORE the
  post-restore remount trigger (cf-deploy-host.yaml:283-305) brings
  /var/www online. Extracting the marker would write to local disk
  under an unmounted directory, which then gets HIDDEN once FSx
  mounts on top — creating a confusing "backed up but invisible"
  state and misrepresenting the file's actual source of truth.

So instead of adding it to BACKUP_PATHS, this commit adds an
explanatory NOTE block in backup-state.sh:170-177 documenting the
deliberate exclusion. Future me (or anyone else) reading the list
now sees WHY the marker isn't there rather than being tempted to
add it "for completeness."

Refresh path when needed: `make create-installed ENV=<env>` on the
deploy-host regenerates the marker from live SSM/drush data
(commit b42a423 added this target).
