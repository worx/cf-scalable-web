### 09:56:46 - Response

Excellent instinct — and here's the good news: **that "check + install if needed" pattern already partially exists.** Let me lay out the current reality and where the gaps are:

## What already exists

**`migrate-db-all`** (in `migration/Makefile`) has an `AUTO=yes` flag that:
- Runs a preflight to check if Drupal is installed
- If missing, auto-invokes `install-drupal ENV=sandbox` and continues
- Then does: db-backup → restore-mysql → run-pgloader → cache-clear

**`migrate-full-all`** wraps `migrate-db-all` + `dispatch-restore-files` + `dispatch-restore-private` + one more cache-clear.

So `make migrate-full-all AUTO=yes` (from Mac, run from `migration/`) gets you 4 out of ~5 things:
1. ✅ Install-if-needed base Drupal
2. ✅ DB migration (mysql + pgloader)
3. ✅ Restore public files
4. ✅ Restore private files
5. ❌ **Missing: `sync-s3-media`** (prod media bucket → sandbox media bucket)
6. ❌ **Missing: `restore-codebase`** (bring in prod's exact codebase + siblings)
7. ❌ **Missing: `make dump-all` beforehand** (must be run separately to populate S3)

## Current best sequence for a fresh sandbox

```bash
# From Mac, in migration/:
cd migration

# 1. Populate S3 with fresh prod dumps (~15-25 min, on jumpbox via SSM)
make dump-all

# 2. Sync media bucket from prod (~5-10 min, on jumpbox via SSM)
make sync-s3-media

# 3. Install-if-needed base Drupal + full DB + files + private restore
make migrate-full-all AUTO=yes

# 4. (Optional) Restore prod codebase + sibling packages
make dispatch-restore-codebase CONFIRMED=yes
```

Then smoke test.

## My recommendation

**Right now — do it in pieces manually.** This is your first fresh-sandbox migration test since we made all the Phase D changes. Each step's output matters as validation. If you wrap it too early and something breaks silently, we've lost the signal.

**After the manual run works** — build a proper `bootstrap-fresh-sandbox` target that wraps:
1. `dump-all` (only if S3 dumps are stale — could check timestamps and skip if fresh)
2. `sync-s3-media`
3. `migrate-full-all AUTO=yes`
4. `dispatch-restore-codebase` (conditionally, based on a flag)
5. Smoke test at the end

That's a real design decision worth thinking through — do we want it always to re-dump prod? Or only if the dumps are older than N hours? Etc.
