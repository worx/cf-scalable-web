### 10:56:05 - Response

That error is fine — expected behavior. The script correctly caught and continued:

> `drush sql:drop returned non-zero (DB may already be empty — continuing)`

The `drush sql:drop` failed because settings.php was partially written by the aborted install-drupal — drush couldn't read a complete config to connect to the DB. The script recognizes this (via the non-zero return code) and moves on. Good defensive design.

The `Removing /var/www/drupal...` step is what matters — that wipes the half-baked composer install so the next `install-drupal` starts clean.
