## The shape of the change

Prod's Drupal reads getenv('AWS_S3_BUCKET') to route s3:// URIs
(observed by Kurt in React2 settings.php:936-941 — bucket falls
back to 'zi-documents' if env var not set). Matching that convention
end-to-end so migrated code paths behave identically across envs.

## What each touched file does

### install-drupal.sh — write flysystem_s3 config into settings.php

New block after the file_public_path / _private / config_sync lines
(existing file-scheme settings). Registers the s3:// stream wrapper
so `file_managed` rows with `s3://YYYY-MM/*.pdf` URIs resolve at
request time.

  \$_media_bucket = getenv('AWS_S3_BUCKET')
    ?: (getenv('ENVIRONMENT_NAME') . '-drupal-media-kv-worxco');
  \$settings['flysystem'] = [
    's3' => [
      'driver' => 's3',
      'config' => [
        'region' => getenv('AWS_S3_REGION') ?: 'us-east-1',
        'bucket' => \$_media_bucket,
      ],
      'cache' => TRUE,
    ],
  ];

PHP-side fallback (`${ENVIRONMENT_NAME}-drupal-media-kv-worxco`)
handles the case where env var isn't propagated yet — settings.php
gets to the right per-env bucket via naming convention rather than
hardcoding any one env's bucket name. No 'key' / 'secret' set —
compute instances use IAM instance role (already has S3 permissions
via cf-iam).

### refresh-env-config — export AWS_S3_BUCKET from SSM

Same pattern used for DRUPAL_DB_HOST, DRUPAL_DB_PASS, etc. Reads
`/${ENV}/s3/media-bucket` (populated by cf-storage-s3.yaml), writes
into `/etc/worxco/envs/${ENV}` as `AWS_S3_BUCKET`. Deploy-host
processes (drush, install-drupal reruns) pick it up on env-source.

Empty tolerated — settings.php's PHP-side fallback catches it.

### configure-php.sh — env[AWS_S3_BUCKET] in PHP-FPM pool config

Same pattern used for DRUPAL_DB_PASS, DRUPAL_HASH_SALT. Fetches
from SSM, adds `env[AWS_S3_BUCKET]` line to the managed BEGIN/END
block inside `/etc/php/${PHP_VER}/fpm/pool.d/www.conf`. PHP-FPM
workers see it via getenv() at request time.
