## 1. test-templates.sh — false-negative on Multi-AZ

    Test:    grep -q 'MultiAZ: true' cloudformation/cf-database.yaml
    Actual:  MultiAZ: !If [MultiAZEnabled, true, false]

Template correctly parameterizes Multi-AZ via `EnableMultiAZ` parameter
and `MultiAZEnabled` condition. Grep for literal `MultiAZ: true` fails
because the value is never a literal. Test was written for a hardcoded
version that never existed.

Fixed to assert BOTH the parameter's presence and the correct wiring
into the DB resource:

    grep -q 'EnableMultiAZ:'                          &&
    grep -qE 'MultiAZ:\s*!If \[MultiAZEnabled'        cloudformation/cf-database.yaml

Now passes cleanly, and would fail if either half broke.

## 2. ssm-report / ssm-remediate — force `--profile default` on no-profile hosts

Symptom (from TODO.md, discovered 2026-04-24):

    make ssm-report
    → "The config profile (default) could not be found"

Root cause:
- Makefile: `--profile $${AWS_PROFILE:-default}` — falls back to
  "default" profile if AWS_PROFILE unset
- ssm-bootstrap.sh: `--profile` was REQUIRED (checked in arg parser)
- Deploy-host has no `default` profile (uses IAM instance role);
  aws bails before doing anything

Fix — allow `--profile` to be OPTIONAL on both sides:

- Makefile targets: `$${AWS_PROFILE:+--profile $$AWS_PROFILE}` —
  passes `--profile` only when AWS_PROFILE is set. Empty → omit.
- ssm-bootstrap.sh: removed PROFILE from the required-args check.
  Replaced every `aws --profile "${PROFILE}"` with
  `aws ${PROFILE:+--profile "${PROFILE}"}` — omits `--profile`
  when PROFILE is empty, falling through to SDK credential chain
  (instance-role → env vars → ~/.aws).

Same fix applied to `ssm-remediate` in the Makefile.

## 3. ssm-audit-params — treat RDS/Cache params as OPTIONAL

Symptom (from TODO.md, 2026-04-24):

    make ssm-audit-params ENV=sandbox
    → exits 1 whenever /sandbox/rds/* or /sandbox/cache/* not deployed
      (which is normal during early-stage sandbox setup)

Fix — distinguish REQUIRED vs OPTIONAL params:

    check_param              — required, missing counts toward exit-1
    check_param_optional     — optional, prints YELLOW "not deployed — OK",
                               tracked separately, doesn't affect exit

RDS (/rds/endpoint, /rds/port, /rds/database) and Cache (/cache/endpoint,
/cache/port) now use `check_param_optional`. FSx, NLB, AMIs, S3 buckets,
/environment/name stay REQUIRED (their absence really does mean broken).

Summary output now shows Found / Missing (required) / Missing (optional)
separately, with each block's remediation hints only if that block has
anything to report.

Exit code: 0 iff no REQUIRED params missing. Optional missing still
prints info + remediation but doesn't fail the audit.
