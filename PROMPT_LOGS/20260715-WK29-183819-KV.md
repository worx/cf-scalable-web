Proposed (guards each fallible step so `set -e` can't silently kill us):
```bash
# Download scripts (--quiet dropped so error text is captured in the log)
if ! aws s3 cp "s3://$BACKUPS_BUCKET/scripts/_common.sh" \
        /opt/deploy-host/scripts/_common.sh; then
  echo "WARN: could not fetch _common.sh from S3 - skipping restore"
elif ! aws s3 cp "s3://$BACKUPS_BUCKET/scripts/deploy-host/restore-state.sh" \
        /opt/deploy-host/scripts/deploy-host/restore-state.sh; then
  echo "WARN: could not fetch restore-state.sh from S3 - skipping restore"
else
  chmod +x /opt/deploy-host/scripts/deploy-host/restore-state.sh
  CONFIRMED=yes DEPLOY_HOST_BACKUPS_BUCKET="$BACKUPS_BUCKET" \
    /opt/deploy-host/scripts/deploy-host/restore-state.sh \
    || echo "WARN: restore-state.sh exited non-zero - partial or no restore"
fi
```

Why this fixes today's failure: if either s3 cp fails, we now emit an audit-friendly WARN and continue instead of dying with `set -e`. The wait-deploy-host-ready target will no longer see cloud-init as failed.
