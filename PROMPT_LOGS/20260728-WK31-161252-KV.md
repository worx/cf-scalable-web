## What to run

**Just `make dump-codebase` tonight. Save `make restore-codebase` for the morning.**

Reasoning:
- `dump-codebase` is safe — only writes to S3, doesn't touch sandbox. If the auto-discovery logic breaks, worst case is a bad tarball in S3.
- `restore-codebase` MODIFIES the running sandbox (atomic swap of `/var/www/drupal` + siblings). Bigger refactor, less battle-tested. You want to be around to watch it.
- Splitting also lets you eyeball the tarball's structure in the morning (`aws s3 cp … - | tar tzf - | head`) before firing the restore — belt-and-suspenders.
