**Message:**
```
refactor(install-drupal): make it self-sufficient (vhost + nginx reload)

Fixes the class of bug caught 2026-07-31 where migrate-full-all AUTO=yes
triggered install-drupal, the install technically succeeded, but the
site returned "no vhost configured for this host" from nginx because
nobody had reloaded the fleet after publishing drupal.conf.

## Semantic change

"install-drupal" now means "installed AND reachable." Before this
commit it meant "drush site:install ran" which left the environment
non-functional. install-drupal-full existed as the "actually usable"
wrapper. That was the root ambiguity.

## New shape

install-drupal
  ├─ step 1: sudo -E bash scripts/deploy-host/install-drupal.sh
  ├─ step 2: make publish-drupal-vhost   (write drupal.conf to FSx)
  └─ step 3: make reload-nginx           (nginx fleet picks it up)

install-drupal-full (unchanged intent; just slimmed the middle)
  ├─ step 1: make install-drupal-remote  (calls install-drupal — now 3-in-1)
  ├─ step 2: make smoke-test-drupal      (was step 4)
  ├─ step 3: make publish-dns            (was step 5, now includes SOA preflight)
  └─ step 4: make smoke-test-public      (was step 6)

## Callers that benefit automatically

- `make install-drupal ENV=sandbox` (operator directly) — now leaves
  a functioning site instead of a half-installed one
- `make migrate-full-all AUTO=yes` — AUTO's install-drupal invocation
  now produces a working site the operator can hit via ALB
- `make install-drupal-full ENV=sandbox` — same end state, just
  fewer explicit steps in its body

## What DOESN'T change

- install-drupal-remote (SSM dispatcher) unchanged; it invokes
  install-drupal via SSM, which now transitively does the vhost + reload
- publish-drupal-vhost and reload-nginx targets themselves unchanged
- publish-dns (with its new SOA preflight from b7c3169) unchanged

## Idempotency

Both publish-drupal-vhost and reload-nginx are idempotent — writing
the same vhost is a no-op; reloading nginx with unchanged config is
graceful. Calling install-drupal on an already-installed env is
still gated by the install marker (script exits early with a warning
if .installed exists), so the follow-on steps don't fire in that path.

## Files Modified

- Makefile — install-drupal target: added steps 2 & 3 with an
  explanatory comment block. install-drupal-full: removed the now-
  redundant steps 2 & 3 (renumbered 4→2, 5→3, 6→4 accordingly),
  updated docstring.

Tests: `make -n install-drupal` shows the 3-step sequence.
`make -n install-drupal-full` shows the slimmed 4-step version
with install-drupal-remote first (which itself does the 3).
```
