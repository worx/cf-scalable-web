Yes — three per-pipeline targets:

| Target | What it does |
|--------|--------------|
| `make build-ami-nginx ENV=sandbox` | Trigger just NGINX pipeline (async) |
| `make build-ami-php74 ENV=sandbox` | Trigger just PHP 7.4 pipeline (async) |
| `make build-ami-php83 ENV=sandbox` | Trigger just PHP 8.3 pipeline (async) |

**Caveat:** each of the three is **async / fire-and-forget** — no wait built in. `make build-amis` is what wraps `build-amis-async + wait-amis` for the "trigger all and wait" experience.

## Two ways to wait

```bash
# Trigger just php83 (returns in ~1 sec), then wait:
make build-ami-php83 ENV=sandbox
make wait-amis ENV=sandbox
```

`wait-amis` polls all 3 pipelines but since nginx and php74 are already at AVAILABLE state from prior builds, it effectively just waits on php83.

Or watch it yourself in the UI: AWS Console → EC2 Image Builder → Image pipelines → `cf-scalable-web-sandbox-php83`.

## One thing to double-check before you fire

Does sandbox have any **PHP 7.4** instances running? If yes, they also need `env[AWS_S3_BUCKET]` eventually — otherwise Drupal running on PHP 7.4 pool won't find the flysystem bucket. Quick check:

```bash
aws --profile ZI-Sandbox autoscaling describe-auto-scaling-groups \
  --auto-scaling-group-names sandbox-php74-asg sandbox-php83-asg \
  --query "AutoScalingGroups[].{ASG:AutoScalingGroupName,Desired:DesiredCapacity,Instances:length(Instances[])}" \
  --output table --region us-east-1
```

If php74 shows `Desired: 0` and `Instances: 0` (typical for a sandbox that's only testing php83), you're safe to skip php74. If it's serving traffic, you'll want to rebuild that one too — either now (parallel, no extra wall-clock) or later.

## Recommended firing sequence right now

```bash
# From your Mac:
make upload-build-configs ENV=sandbox    # pushes new configure-php.sh to S3 — few seconds
make build-ami-php83 ENV=sandbox          # trigger — returns in ~1 sec
make wait-amis ENV=sandbox                # blocks ~10-15 min
# (once wait-amis returns AVAILABLE:)
make update-ami-params ENV=sandbox        # writes new AMI ID to SSM
make deploy-compute-php ENV=sandbox       # CFN update — launch template picks up new AMI
# then start-instance-refresh or terminate-instances as we discussed
```
