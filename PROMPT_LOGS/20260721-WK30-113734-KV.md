`migration/scripts/deploy-host/restore-codebase.sh` — 6-phase pattern
matching restore-files.sh / restore-private.sh:

  1. Preconditions (root, tools, /var/www mounted, target parent exists)
  2. Confirmation (destructive — replaces sandbox's Drupal codebase)
  3. Fetch tarball (cached; FORCE_DOWNLOAD=yes overrides)
  4. Extract to .NEW dir — NO --strip-components (dump-codebase.sh's
     `tar czf - -C $DRUPAL_ROOT .` produces relative members like
     `./composer.json`, `./web/`, not a top-level wrapper dir)
  5. Ownership (root:www-data) + perms (u=rwX,g=rwX,o=)
  6. Atomic swap + PRESERVE_FROM_BAK

                                     install-drupal.sh from a
                                     sandbox-specific template. Prod's
                                     settings.php has PROD DB endpoints
                                     and secret paths and would
                                     immediately point sandbox at
                                     prod's RDS if not preserved.

                                     install-drupal's re-run check still
                                     looks at it and we want that gate
                                     working correctly).

(they're standard Drupal paths), so the preserve-copy has a landing
spot. `mkdir -p` on the parent belt-and-suspenders anyway.
