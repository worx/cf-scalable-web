### 20:15:51 - Response

Short answer: **no, you don't need to redeploy — bootstrap.sh is designed to be idempotent, and the only piece that strictly requires a new UserData run is the swap resize (fixable in place)**. Two paths:

## Fast path — apply in place, ~5 minutes

On the deploy-host:

```bash
# 1. Get the new scripts + template
cd ~/projects/cf-scalable-web && git pull

# 2. Re-run bootstrap.sh — installs pgloader/mariadb-server/mlocate/pv/htop/
#    session-manager-plugin, disables mariadb, adds mariadb-client
sudo bash scripts/deploy-host/bootstrap.sh 2>&1 | tee /tmp/rebootstrap.log

# 3. Manually resize swap (UserData won't fire again on this instance)
sudo swapoff /swapfile
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
free -h    # confirm swap = 4.0G

# 4. Quick sanity
which pgloader && pgloader --version
systemctl status mariadb --no-pager     # inactive, disabled
session-manager-plugin --version
locate --version
```

**What this path does NOT test:** the UserData auto-restore hardening we just committed. That code path only fires on instance replacement.

## Full path — destroy/redeploy, ~25 minutes

```bash
# From your Mac
cd ~/Work/dev/cf-scalable-drupal
make backup-deploy-host              # belt+suspenders — capture today's state
make destroy-deploy-host CONFIRMED=yes
make deploy-deploy-host
```

Verifies **everything**, including the auto-restore fix that was the whole reason for this session's work.

## My recommendation

**Fast path today, but plan a full redeploy soon.** Reasoning:

- Auto-restore is the highest-value thing to verify (it's what actually broke), but the fix was mechanical and code-reviewable — the risk of "we broke it worse" is low
- You just spent yesterday on a teardown/rebuild — no need to burn 25 minutes again if you don't need to right now
- Getting mariadb/pgloader/swap in place TODAY unblocks any test-migration work
- The next natural trigger for a rebuild (AMI drift, an unrelated CFN change to cf-deploy-host.yaml, quarterly hygiene) is a fine time to verify auto-restore end-to-end. It'll happen. It doesn't need to happen tonight.

**One thing worth doing regardless:** `make backup-deploy-host` from your Mac right now, so today's fresh apt state is captured. That way even if fast-path in-place changes wander, the backup tarball reflects the "good known" state.
