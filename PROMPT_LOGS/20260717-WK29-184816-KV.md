refactor: gate Drupal ops on drush+settings.php (not .installed marker)

Implements the pattern captured in
docs/memory/structural-checks-over-markers.md (commit da73889): the
`.installed` marker file is fine to keep for informational content
(install date, DB endpoint, secret paths — see install-drupal.sh:634-644),
but it MUST NOT be the correctness gate — its absence produces false
negatives on installs that predate the marker convention, blocking
legitimate operations.

Discovered live 2026-07-17: sandbox Drupal was serving traffic just
fine but had no `.installed` file, and every marker-based check errored
with "Drupal not installed" until the marker was backfilled by hand.

## The structural check

`[ -x /var/www/drupal/vendor/bin/drush ] &&
 [ -f /var/www/drupal/web/sites/default/settings.php ]`

If both exist, Drupal is deployed and drush can bootstrap it — which
is the actual precondition every downstream operation cares about.
Zero false negatives across install pathways (script, manual composer,
git checkout, etc.).
