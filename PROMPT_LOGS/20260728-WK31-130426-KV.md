## We haven't migrated the database. Only the files.

| Operation | What it moves | Status |
|-----------|---------------|--------|

## What "migrating the DB" actually means

The prod DB lives in **MySQL** (in prod's account). Sandbox runs **PostgreSQL** (different engine entirely). You can't just copy the file — the two engines don't speak the same on-disk format.

The two-step DB migration in the runbook is:

1. **restore-mysql** — pull `dumps/zinew.sql` from S3 (the mysqldump Zac made ~10 days ago), load it into a **temporary MariaDB** on the deploy-host. This gives us a MySQL-compatible source to convert from.
2. **run-pgloader** — pgloader is a specialized tool that reads MySQL tables and writes them into PostgreSQL, translating types, casing, indexes, etc. as it goes. That's what actually lands prod's data into sandbox's RDS.

Neither of those has run yet in this session. Your current sandbox DB is the **pre-existing sandbox DB** — created by `install-drupal.sh` at some earlier point, with whatever content sandbox happened to have (which is basically nothing / a fresh Drupal install with no reports).

That's why:
- **Sandbox loads** — the empty-ish sandbox DB is there and functional.
- **A prod report URL 404s** — that entity ID exists in prod's DB, not sandbox's.
- **Even after DB migration, PDFs would 404** if we hadn't done the S3 work first — because `file_managed` rows would reference `s3://` URIs but the bucket would be empty.

## Why we did it in this order

We did S3 first so that when you run the DB migration, everything lines up on the first try:
1. DB migration lands `file_managed` rows referencing `s3://YYYY-MM/whatever.pdf`
2. Drupal looks up the file via flysystem → sandbox media bucket
3. File is there (we synced it earlier) → PDF renders

If we'd done them the other way (DB first, files second), you'd hit a window where every PDF link was broken.

## Analogy

Think of a house move:
- **S3 migration** = moving all the boxes (books, dishes, clothes) into the new house
- **DB migration** = moving the address book that tells you *which* boxes hold what, and how the furniture is arranged

We've moved the boxes. Nothing in the new house has been unpacked or arranged yet. The address book is still at the old house.

## What to do next

After it runs, `/admin/zoning-info/reports/conformance-reports/92284` should render — the entity will exist, the file reference will resolve, and flysystem_s3 will serve the PDF from the bucket we populated.
