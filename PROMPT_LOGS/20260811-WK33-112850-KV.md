feat(migration): temporary RDS upsize wrapper (migrate-{db,full}-all-boosted)

Confirmed 2026-08-11: pgloader wall time is capped by RDS commit
latency, not by migrate-host size. Both deploy-host and migrate-host
hit the same 50-52 min ceiling against sandbox's db.t4g.micro (2
burstable vCPU / 1 GiB RAM, gp3 3000 IOPS / 125 MB/s baseline).

This change adds a temp-RDS-upsize wrapper that boosts sandbox RDS
from db.t4g.micro to db.r7g.xlarge (4 vCPU / 32 GiB) for the
migration window, then reverts. Bash trap ensures revert always
runs — even on migration failure — so RDS is never stranded at the
expensive tier.

Design compromises:

1. Class-only boost by default. IOPS/throughput bumps require gp3
   storage >= 400 GiB (RDS constraint). Sandbox is 20 GiB and
   storage is one-way (can grow, can't shrink) — bumping to 400 GiB
   just for per-migration IOPS would create a permanent $30-40/mo
   storage floor. Class-only still delivers the biggest win.
   --target-iops / --target-throughput flags are available for
   environments where the storage is already large enough.

2. Save/revert semantics via SSM parameter
   /<env>/rds/pre-migration-config. Records ACTUAL pre-boost values
   (not hardcoded assumptions), plus a WillModifyIops flag so
   revert only touches what boost touched.

3. Idempotency: boost refuses if the SSM parameter already exists
   (unreverted prior boost). Revert no-ops if the SSM parameter is
   absent (nothing to revert). Boost failure-path trap deletes the
   SSM parameter so retry isn't blocked.

4. Wrapper script (rds-boosted-migration.sh) does the trap-and-run,
   invoked from Make. Bash's trap semantics are more reliable than
   Make + /bin/sh (dash) for error-path cleanup.

Cost per run: ~$0.13 (r7g.xlarge tier for the boosted window).
Break-even: any single migration saving > 15 min wall time.

Files created:
- scripts/rds-migration-tuning.sh    (boost + revert impl)
- scripts/rds-boosted-migration.sh   (Make-invoked wrapper w/ trap)

Files modified:
- migration/Makefile                 (2 new targets: -boosted variants)

Usage:
  cd migration
  make migrate-db-all-boosted   ENV=sandbox AUTO=yes
  make migrate-full-all-boosted ENV=sandbox AUTO=yes

Escape hatch: SKIP_RDS_BOOST=yes bypasses boost + revert entirely.

Verified: bash -n clean on both scripts, Makefile targets parse. Live
boost + revert cycle NOT yet tested end-to-end — that's the next
integration test on Kurt's next full-cycle run.
