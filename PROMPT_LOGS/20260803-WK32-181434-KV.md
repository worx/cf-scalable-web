**Found it — 66 bytes is a stub 404 from somewhere in front of the real ALB.** Curl-via-deploy-host gets 5754 bytes because it uses `--resolve` to hit the ALB IP directly. Safari on your Mac is hitting something else entirely.

**Most likely cause**: leftover `/etc/hosts` entry on your Mac pointing at a stale ALB IP from before tonight's destroy-all/deploy-all cycle. The ALB IPs change every rebuild.

**On your Mac** (not deploy-host):

```bash
grep -i zoning /etc/hosts
```

If you see any lines for `sandbox.envs.zoning-info.com`, that's your problem — they pin the DNS to a stale IP. Remove them:

```bash
sudo sed -i '' '/sandbox\.envs\.zoning-info\.com/d' /etc/hosts
```

Then flush DNS cache:

```bash
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
```

Reload the Safari tab. Should render the "Test" page (real content) immediately.

If `/etc/hosts` had nothing, then something else is intercepting — dig from your Mac:

```bash
dig sandbox.envs.zoning-info.com +short @8.8.8.8
```

Compare that to the current ALB IPs (`52.6.241.192` `54.164.235.196` per your smoke test). If they don't match, DNS is stale somewhere.
