**Mixed answer** — depends on the target:

- **`dump-all`, `migrate-full-all`, `smoke-test-public`** — YES on deploy-host. Their docstrings say `[FROM: Mac|deploy-host, PROFILE: ZI-Sandbox + ZoningInfoAdmin]`. Deploy-host has the needed cross-account IAM.

- **`deploy-all`** — probably NO on deploy-host. It fires ~13 `aws cloudformation deploy` calls in parallel. That needs CFN admin permissions on the ZI-Sandbox account. Your deploy-host has a scoped instance role (SSM, migration S3, Secrets Manager for `worxco/*/drupal/*` — but not full CFN admin). Per your CLAUDE.md, `.aws/credentials` stays on your Mac, so the deploy-host doesn't have your user credentials either.

**If you want a "run everything unattended and go read" workflow**, two options:

**Option A — Mac + caffeinate** (simplest):
```bash
caffeinate -i bash -c '{
cd /Users/kurtvanderwater/Work/dev/cf-scalable-drupal && \
make deploy-all ENV=sandbox && \
cd migration && \
make dump-all CONFIRMED=yes && \
make migrate-full-all AUTO=yes && \
cd .. && \
make smoke-test-public ENV=sandbox && \
echo "=== FULL TEST CYCLE PASSED ==="
} 2>&1 | tee /tmp/full-test-$(date +%Y%m%d-%H%M%S).log'
```
`caffeinate -i` keeps the Mac from sleeping while the shell runs. Lid can close, screen can lock — the process keeps going. Log survives on Mac.

**Option B — Split it**: `deploy-all` on Mac (needs to complete anyway before migration can run), then ssh to deploy-host in tmux for the rest:
```bash
# on Mac:
cd /Users/kurtvanderwater/Work/dev/cf-scalable-drupal && make deploy-all ENV=sandbox

# then ssm-deploy-host, tmux, cd migration, chain the rest
```

**My recommendation: Option A.** One paste, one log, no ssh dance, no context switching. `caffeinate -i` is the whole trick.
