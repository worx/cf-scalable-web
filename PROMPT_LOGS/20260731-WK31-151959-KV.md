# nginx → PHP-FPM Request Routing Architecture Report

## 1. Request Flow

**ALB → nginx (port 80) → NLB → PHP-FPM (port 9000)**

- `cf-compute-alb.yaml:157–168` — ALB target group forwards to nginx on port 80, ELB health check hits `/health` (default per `cf-compute-alb.yaml:69`).
- `image-builder/configs/nginx/nginx.conf:84–103` — the baseline nginx has a `listen 80 default_server` block that OWNS `default_server` and serves `/health` locally (returns `200 "ok\n"`) and 404s everything else. This intentionally decouples fleet health from Drupal install state.
- `image-builder/configs/nginx/nginx.conf:108` — `include /etc/nginx/shared/sites-enabled/*.conf;` is a glob. Multiple vhosts drop in automatically — **the plumbing is already multi-vhost-capable**.
- `/etc/nginx/shared` is an NFS mount of the FSx subtree `/fsx/nginx` (mounted in `image-builder/components/install-nginx.yaml:176–178` at boot by `configure-nginx.sh`).
- Vhost file on disk (FSx): `/fsx/nginx/sites-enabled/drupal.conf`, appears on every nginx host at `/etc/nginx/shared/sites-enabled/drupal.conf`. Written by both `scripts/publish-drupal-vhost.sh:70,79` and `scripts/deploy-host/install-drupal.sh:656,660`. Filename convention today: single fixed `drupal.conf`.

## 2. PHP Version Selection

The mechanism is **NOT** true port-based routing at the request level — the port choice is baked into the vhost's `fastcgi_pass` directive.

- `image-builder/components/install-nginx.yaml:186–195` — `configure-nginx.sh` writes `/etc/nginx/conf.d/upstream-php.conf` at boot with TWO named upstreams pointing at the internal NLB DNS: `upstream php74 { server $NLB:9074; }` and `upstream php83 { server $NLB:9083; }`.
- `cf-compute-nlb.yaml:92–166` — the NLB has two TCP listeners (9074, 9083), each forwarding to a separate target group (`php74-tg`, `php83-tg`), both pointing at PHP-FPM on port **9000** (`Port: 9000` on both TGs). Two independent ASGs (`cf-compute-php.yaml:278, 316`) register into these — one PHP 7.4 fleet, one PHP 8.3 fleet.
- The vhost decides which upstream via `fastcgi_pass  php83;` (hardcoded at `publish-drupal-vhost.sh:107` and `install-drupal.sh:694`). Neither publish nor install currently takes a PHP-version arg — both **hardcode `php83`**.

So: "port-based routing" is really "upstream-name-based" from nginx's POV; the port merely distinguishes the two NLB listeners so the same NLB can front two PHP fleets.

## 3. Shape of the drupal.conf Vhost

The two writers (publish-drupal-vhost.sh:87–130, install-drupal.sh:666–723) produce nearly identical output:

- Single `server { listen 80; server_name $SITE_NAME; root $INSTALL_DIR/web; index index.php; ... }` block — **no** `default_server` flag (intentional, see nginx.conf comment).
- Per-site knobs: `server_name`, `root` (always `/var/www/drupal/web`), `access_log`/`error_log` paths (`drupal_access.log`/`drupal_error.log`), and the `fastcgi_pass` upstream name.
- Locations: `/` → `try_files … /index.php`; `\.php$|^/update.php` → FastCGI with standard `fastcgi_params`, `SCRIPT_FILENAME`, `PATH_INFO`, `HTTP_PROXY ""`, 60s read timeout; security denials for dotfiles + `/sites/*/private/`; special CSS/JS/styles aggregate handling that falls through to `@rewrite → /index.php` so Drupal 11 can lazy-build.
- `SITE_NAME` comes from SSM `/$ENV/drupal/site-name` (default `drupal-$ENV.test`) — see `publish-drupal-vhost.sh:61` and `install-drupal.sh:102`.

## 4. Environment Variables → PHP-FPM

- `image-builder/configs/php/8.3/www.conf:9–46` (identical structure in 7.4/www.conf) — baseline pool `[www]`, `listen = 0.0.0.0:9000`, `clear_env = yes`. **Single pool per instance.**
- `image-builder/configs/configure-php.sh:135–180` — at boot, `configure-php.sh` reads SSM/Secrets Manager and **rewrites a marker-delimited BEGIN/END worxco-boot block** appended to `www.conf`, injecting `env[ENVIRONMENT_NAME]`, `env[DRUPAL_DB_HOST]`, `env[DRUPAL_DB_PORT]`, `env[DRUPAL_DB_NAME]`, `env[DRUPAL_DB_USER]`, `env[DRUPAL_DB_PASS]`, `env[DRUPAL_HASH_SALT]`, `env[AWS_S3_BUCKET]`, `env[DRUPAL_SITE_NAME]`, plus a `php_value[session.save_path]` for Valkey.
- The comment at `configure-php.sh:32–35` explicitly notes PHP-FPM does not accept `include=` inside a pool section, so drop-ins per-site would have to be **separate pool blocks**, not includes into `[www]`.
- `settings.php` (generated at `install-drupal.sh:445–557`) is single-tenant: reads flat `getenv('DRUPAL_DB_*')`, `getenv('DRUPAL_HASH_SALT')`, `getenv('AWS_S3_BUCKET')` — no site-scoped resolution.

**Multi-site implications**: There is no per-request env resolution today. To go multi-site, options are (a) one FPM **pool per site** each listening on its own port, with nginx `fastcgi_pass` chosen per vhost, and per-pool `env[]` blocks; or (b) keep one pool per PHP version and dispatch env by `SERVER_NAME`/vhost-provided `fastcgi_param` (moves site→credential mapping into settings.php via a lookup table). Option (a) matches the existing shape (per-pool `env[]` already exists) and doesn't require refactoring settings.php.
