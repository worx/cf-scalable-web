## Proposed additions to bootstrap.sh

**Drupal management group (extend line 383):**

   mariadb-client \

   nfs-common \

*(`pgloader` pulls SBCL + friends automatically. `mariadb-server` auto-enables the systemd unit at install — no manual start needed. Memory idle cost is small.)*

**New step (after Composer/Drush, or near AWS CLI):**
```bash
# ============================================================
step "AWS session-manager-plugin (SSM tunneling from deploy-host)"
# ============================================================
# Not in Ubuntu apt — pull .deb directly from Amazon.
# ARM64 build (deploy-host runs Graviton).
cd /tmp
curl -sS \
  "https://s3.amazonaws.com/session-manager-downloads/plugin/latest/ubuntu_arm64/session-manager-plugin.deb" \
  -o session-manager-plugin.deb
dpkg -i session-manager-plugin.deb || apt-get -f install -y
rm session-manager-plugin.deb
cd /
session-manager-plugin --version || echo "WARN: session-manager-plugin install may have failed"
```

## Trade-off worth naming

- **Install-time cost**: pgloader + SBCL is ~200MB and a couple minutes extra at every AMI rebuild. mariadb-server is another ~100MB.
- **Runtime cost**: mariadb-server idle is ~100MB RAM. Not scary on the deploy-host instance class, but real.
- **Alternative**: gate them behind a make target (`make migration-prep`) that's idempotent — only installed when you're actually about to do a test migration.

My call: **bake them in.** You asked for exactly this in a WK24 prompt log ("Bake pgloader and mysql-client into bootstrap.sh") and never got to it. The migration workflow is now a first-class capability, not a one-shot.
