## Batch delete by index OR name

new scripts/deploy-host/db-delete-backup.sh <env> <selector> [<selector> ...]
new Makefile target: make delete-db-backup ENV=<env> SELECT="1 3 5"

Selector rules:
- Numeric — resolved against the current listing at run time
- Full DB name — verified to match the `<prefix>_backup_%` safety
  pattern, refuses anything else (won't touch the live app DB)
- Mix of both accepted in a single call

Multiple selectors → batch delete in one confirmation prompt showing
every resolved name. CONFIRMED=yes skips the prompt.

Each DROP DATABASE runs in its own psql invocation so a single
failure (e.g., a backup with active connections) doesn't halt the
batch — every attempt is logged individually.

## Safety

- Pattern match: refuses to delete anything not matching
  `<prefix>_backup_%`. Even if someone types `SELECT=drupal` by
  accident, the script bails with "not in the listing" before
  reaching psql.
- Index → name resolution is stateless. If backups are created or
  deleted between `list` and `delete`, indexes may shift — for
  single-operator use this is fine; scripting flows should use
  full names.

## Race window note

Documented inline in both scripts. Numeric selectors carry a small
race between "operator ran list-db-backups and read the number"
and "operator invoked delete-db-backup with that number" — if
another backup was created (or removed) in the meantime, the
index-to-name map can shift. Not a corruption risk (still refuses
anything not matching the backup pattern), just a "you might delete
a different backup than you thought" possibility. For scripted /
automated flows, use full DB names.
