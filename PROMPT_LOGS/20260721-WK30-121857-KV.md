## What this delivers

via jumpbox's native IAM role, writes DIRECTLY to sandbox's
`sandbox-drupal-media-kv-worxco` bucket via the cross-account bucket
policy added in the prior commit. No intermediate hop through the
migration bucket — one `aws s3 sync` moves the data end-to-end.

Incremental. First run copies everything (probably several GB
depending on `zi-documents` size). Subsequent runs only transfer
objects that are new/modified since last sync. Delete is OFF by
default — orphaned objects in sandbox (deleted from prod) stay
in sandbox unless `DELETE_ORPHANED=yes` is set.

## Structure

Follows the same 4-phase pattern as other jumpbox-side scripts:

  1. Preconditions — root, aws CLI, source readable + target
                      listable (verifies cross-account policy is
                      actually attached)
  2. Confirmation — approximate source size printed for context
  3. sync         — aws s3 sync with source+dest region flags
  4. Report       — first 10 keys in target for visual verification
