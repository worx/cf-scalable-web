feat(storage-s3): optional cross-account write policy on MediaBucket for prod → sandbox media sync

Group A item 2, sub-work 1 of 3.

Adds an optional BucketPolicy to MediaBucket in cf-storage-s3.yaml.
Gated on two new parameters (both default empty → prod stack unchanged);
setting both on sandbox lets the prod jumpbox `aws s3 sync` directly
from prod's media bucket into sandbox's, eliminating the intermediate
hop through the migration bucket that would otherwise be needed.

## The two new parameters

- MigrationSourceAccountId       — 12-digit AWS account ID (empty on prod)
- MigrationSourceRoleArnPattern  — IAM role ARN pattern with wildcard
                                    (empty on prod; ties Principal
                                    scoping to a specific role in the
                                    source account, not "any role")

When both are non-empty the `EnableMigrationSourceWrite` condition
fires and MediaBucketMigrationSourcePolicy is created with the same
principal-scoping pattern used by cf-migration-bucket.yaml:129.

## Why "both non-empty" and not "either"

Belt and suspenders — the Principal AWS is scoped to the SOURCE
account root (only that account's principals are candidates), and
the aws:PrincipalArn condition narrows to the specific role. Empty
account ID with a non-empty ARN pattern would produce a garbled
Principal ARN like `arn:aws:iam:::root` which is invalid. Empty
ARN pattern with a non-empty account ID would grant write to
ANY role in that account. Neither case is what we want; requiring
both prevents both misconfigurations.

## Prod safety

The default value for both parameters is empty. Prod's stack
deploys without the parameters set (they're not in
`cloudformation/parameters/production.json`). Condition evaluates
false, no policy attached, no behavior change on prod media bucket.

## Sandbox activation

`cloudformation/parameters/sandbox.json` sets both:
  "MigrationSourceAccountId": "978068244875"    (prod account)
  "MigrationSourceRoleArnPattern": "arn:aws:iam::978068244875:role/cf-migration-jumpbox-*"

Same account/role that already has write to `sandbox-migration-kv-worxco`
via cf-migration-bucket.yaml — this just extends the same principal's
access to include `sandbox-drupal-media-kv-worxco`.
