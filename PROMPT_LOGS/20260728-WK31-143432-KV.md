## Design choice — auto-discover vs. hardcode

I want to lean into **auto-discover from composer.json** (with a hardcoded env-var override for edge cases). Reasons:

- Self-healing: if a third sibling package gets added to prod later, next dump picks it up automatically. No script edit needed.
- Same data source composer already uses, so no risk of the list drifting from reality
- The one-time complexity cost is small (`jq -r` on `composer.json`'s repositories section)

Fallback logic:
```bash
SIBLING_MODULES="${SIBLING_MODULES:-}"
if [ -z "$SIBLING_MODULES" ]; then
  # Read composer.json path-repos from React2
  SIBLING_MODULES=$(ssh ... "jq -r '.repositories[] | select(.type == \"path\") | .url' \
    $DRUPAL_ROOT/composer.json | xargs -n1 basename | tr '\n' ' '")
  [ -z "$SIBLING_MODULES" ] && SIBLING_MODULES="entity_bundle_manager filtered_entity_reference"
fi
```
