### 21:02:53 - Response

Classic DNS negative-cache bite. We've hit this before — memory file `macos-dns-negative-cache.md` covers it. Symptom:

- `dig +short @8.8.8.8` returns IPs → Route 53 change propagated to Google ✓
- `wget` says "No address" → local system resolver still has the pre-publish NXDOMAIN cached

The system resolver got a NXDOMAIN answer earlier tonight (before publish-dns ran) and cached the "no such record" answer for its full TTL (usually 5-15 min). Even though the RECORD now exists, the RESOLVER remembers it doesn't.

## Fix — flush the caches

**On deploy-host (Ubuntu with systemd-resolved):**
```bash
sudo resolvectl flush-caches
```

**On your Mac (if Safari also fails):**
```bash
sudo dscacheutil -flushcache
sudo killall -HUP mDNSResponder
```

Also try Safari in **private window** — WebKit maintains its own DNS cache separate from macOS's.

## Verify after flush

```bash
# On deploy-host:
getent hosts sandbox.envs.zoning-info.com
# expected: 2 IPs (the ALB's)

# Then re-wget:
wget -O /dev/null https://sandbox.envs.zoning-info.com/ 2>&1 | tail -5
```

## Alternative — just wait

Negative-cache TTLs are usually 5-15 min. If you don't want to flush and don't mind waiting a coffee, it self-heals.
