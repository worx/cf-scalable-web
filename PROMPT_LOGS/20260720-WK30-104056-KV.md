## Broader observation

Any script that bootstrap.sh installs as a copy (`use-env`, `refresh-env-config`, `worxco-refresh-env-config.sudoers`) has this same "git pull doesn't propagate" property. Options for the future:

1. **Convention: rerun bootstrap.sh after pulling script updates on deploy-host.** Kurt's already familiar with this pattern for AMI installs.
2. **Make target: `make refresh-deploy-host-scripts`** — one command re-installs the small set of copied scripts to /usr/local/sbin/. Fast (~seconds), targeted, no full bootstrap.
3. **Symlink instead of install** — `ln -sf` from /usr/local/sbin/ to the git checkout. Then git pull immediately takes effect. Downside: assumes the checkout stays put.

Worth a follow-up? Same trap could hit us with `use-env` next time we touch it.
