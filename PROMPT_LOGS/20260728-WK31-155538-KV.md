feat(migration): auto-discover composer path repos in dump/restore

Fixes the gap that surfaced during last night's end-to-end S3 media
migration test: our sandbox rebuild was missing two custom local packages
(`entity_bundle_manager`, `filtered_entity_reference`) that live outside
the Drupal root and are referenced from composer.json as path

in those packages weren't registered, and the migrated DB blew up on
methods that only exist in bundle subclasses.

Rather than hardcode "these two folders" — Zac is likely to add more —
the fix auto-discovers them at dump time.

## dump-codebase.sh — auto-discovery + multi-top-level tar

Phase 3 (metadata) gains a discovery step: SSH into React2, `jq -r`
composer.json's `repositories[type=path].url` entries. Each `../foo`
sibling that actually exists on disk gets added to `SIBLING_MODULES`.

Escape hatches:
- `SIBLING_MODULES="foo bar"` overrides discovery with a literal list
- `SIBLING_MODULES=none` skips both (legacy Drupal-root-only behavior)
- Discovery failures fall back to legacy behavior with a WARN

Phase 5 (tar) restructured. The tar base moved from `-C $DRUPAL_ROOT`
(with `.` as the member) to `-C $(dirname $DRUPAL_ROOT)` (with
`$(basename $DRUPAL_ROOT) $SIBLING_MODULES` as the members). Resulting
archive has multiple top-level dirs:

  zoning_info_platform/…    (Drupal root)
  entity_bundle_manager/…   (sibling, if discovered)
  filtered_entity_reference/…  (sibling, if discovered)

Excludes are now split into two arrays:
- `GLOBAL_EXCLUDES` (.git, .ddev) — bare names; tar matches at any
  depth, so applies to Drupal root AND every sibling
- `DRUPAL_EXCLUDES` (settings.php, files/, private/, etc.) — must
  be prefixed with `$DRUPAL_BASENAME/` at tar time since the tar
  base is one level up

## restore-codebase.sh — significant refactor

Instead of extracting straight into `$TARGET_DIR.NEW.STAMP`, the new
flow extracts to a staging directory (`/var/www/.RESTORE-STAGING.STAMP`)
and iterates over each top-level dir:

1. Identify the Drupal root by heuristic: "the top-level dir containing
   a composer.json." If zero → error, if more than one → error.
2. For the Drupal root: swap into `$TARGET_DIR` (e.g., `/var/www/drupal`)
   with the existing preserve-list dance (settings.php, .installed).
3. For each sibling: swap into `$(dirname $TARGET_DIR)/${sibling_name}`
   (e.g., `/var/www/entity_bundle_manager`). No preserve-list — siblings
   don't have sandbox-managed files.
4. Each swap is atomic (existing → .BAK.STAMP, .NEW.STAMP → target).
5. Cleanup staging dir.

Swap logic extracted into a `swap_one` shell function so drupal-root
and sibling paths share exactly the same idiom.

BACKWARD COMPAT: If the tarball has `composer.json` at its ROOT
(the legacy "bare" layout produced by the old dump-codebase.sh), the
staging tree is treated as the Drupal root itself and there are no
siblings to swap. Old tarballs restore correctly.
