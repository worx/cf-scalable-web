Got it — pattern is `v<major>.<minor>.<patch>-<kebab-case>`, so we want `v0.5.0-migration-ready`. Since git has no rename primitive for tags, standard fix is delete-then-recreate on the same commit.

Paste this — cleans up `050` locally + on origin, then creates the correctly-named tag on the exact same commit:

```bash
# Delete the misnamed tag locally + on origin
git tag -d 050
git push origin --delete 050

# Create the correctly-named annotated tag on current HEAD (same commit we already tagged)
git tag -a v0.5.0-migration-ready -m "Migration Ready — full migration cycle working end-to-end"

# Push the new tag
git push origin v0.5.0-migration-ready

# Verify
git tag -l | tail -6
git show v0.5.0-migration-ready --stat --oneline | head -5
```

The `git tag -a` (annotated) matches your existing pattern — annotated tags carry a message + tagger info + timestamp; lightweight tags (`git tag` without `-a`) don't. All your v0.x tags appear to be annotated.

Since you're the only user of the repo, deleting the pushed `050` tag has zero blast radius — no coordination needed.
