ALB_DNS=$(aws cloudformation describe-stacks --stack-name cf-scalable-web-sandbox-compute-alb --query "Stacks[0].Outputs[?OutputKey=='ALBDnsName'].OutputValue" --output text --region us-east-1)

- **After migrate-full-all:** deploy-host smoke test (`curl --resolve`, DNS-bypassed) confirms Drupal serves 200. Then the `/etc/hosts` line printed again as a reminder.

## Note about tmux behavior

Sequential paste — if any command errors, the NEXT command still runs (bash default without `set -e`). In practice:
- If deploy-all fails, the ALB lookup gets the OLD stack's data (or errors) and migrate-full-all fails obviously
- The 3-hour total is same either way — a fail-early wouldn't save time

If you want fail-early, prepend `set -e` on its own line at the top. Sequential-noise is my default because errors in `make ...` are visible red text that you'll notice mid-run.

## Kraken VPN alternative

You mentioned Kraken as an option — that would work too. VPN sends your queries out via Kraken's exit resolver, which has never asked about `sandbox.envs.zoning-info.com` so no negative cache. Safari-through-VPN would resolve fresh. Just switch VPN on when you want to smoke test.

Either approach works. Choose whichever's less friction for you.
