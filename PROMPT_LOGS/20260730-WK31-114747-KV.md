```
feat(polish): SSM poll uses '|' every 5th dot for eyeball timing

Both migration SSM dispatchers (_ssm-run-deploy-host.sh and
_ssm-run-jumpbox.sh) print '.' every poll tick during SSM
send-command polling. On long-running commands, the wall of dots
gives no sense of elapsed time.

Small polish per Kurt: increment a counter each poll, print '|'
every 5th one instead of '.'. Poll interval is 30s, so:
  '....|'       = 5 polls  = ~2.5 min
  '....|....|'  = 10 polls = ~5   min
  15 tick block = ~7.5 min
etc. Operator can eyeball elapsed time by counting the '|' groups
instead of squinting at a wall of dots.

Preview: `....|....|..` = 12 polls (~6 min).

## Design notes

- Counter increments ONLY on the actual poll case (InProgress|Pending|
  Delayed), not on Success/Failed/etc. exits. So DOT_COUNT always
  equals real polls made.
- Modulo 5 chosen for arithmetic ease + convenient time markers
  (30s * 5 = 2.5 min per '|'). Adjustable via one integer if a
  different interval fits better in the future.
- No changes to POLL_INTERVAL or POLL_TIMEOUT semantics.
- Same change to both dispatchers (identical polling loops); the
  polling logic is duplicated between them — factoring into
  _common.sh would eliminate the duplication but is out of scope
  for a small polish commit.

## Files Modified

- migration/scripts/_ssm-run-deploy-host.sh — counter init + case
  block updated
- migration/scripts/_ssm-run-jumpbox.sh — same change

Tests: bash -n clean on both scripts; standalone preview loop
confirms the visual output.
```
