## What's new

### migration/pgloader/zinew.load.tmpl (NEW)

Committed pgloader spec template with the WITH/CAST clauses that came out of
the WK28 tuning work:

  WITH include drop, create tables, create indexes, reset sequences,
       foreign keys, downcase identifiers,
       batch rows = 250, prefetch rows = 250,
       workers = 2, concurrency = 1

  CAST type tinyint when (= 1 precision) to boolean drop typemod using tinyint-to-boolean,
       type datetime to timestamptz drop default drop not null using zero-dates-to-null,
       type date drop not null drop default using zero-dates-to-null,
       type timestamp drop default drop not null using zero-dates-to-null

Source is hard-coded to the local scratch DB (mysql://worxco:localscratchpass
@127.0.0.1:3306/zinew — created by restore-mysql.sh; credentials not
sensitive). Target uses envsubst placeholders (${DRUPAL_DB_*}, ${SANDBOX_PW_ENC})
that are resolved at run time by the wrapper.

### migration/scripts/deploy-host/run-pgloader.sh (NEW)

Six-phase wrapper matching restore-mysql.sh's shape:

  1. Preconditions   — root, tools (pgloader/psql/jq/envsubst/shred/aws),
                       template present, MariaDB running (auto-starts),
                       source DB has tables (fails fast if restore-mysql.sh
                       hasn't been run yet)
  2. Env sourcing    — source /etc/worxco/envs/sandbox, URL-encode SANDBOX_PW
                       via jq if only the raw form is set, RDS TCP reachability
  3. Confirmation    — clearly names the destructive scope (include drop)
                       and honors CONFIRMED=yes
  4. Render          — envsubst template → /tmp/zinew.load, chmod 600
  5. Run             — pgloader --dynamic-space-size 4096
                                 --no-ssl-cert-verification /tmp/zinew.load
  6. Cleanup/verify  — shred /tmp/zinew.load, query target for table count,
                       warn if target count << source count

Traps combine shred + log_upload_and_exit into one EXIT handler so a killed
run can't leak the RDS password on disk. Bash's single-trap-per-signal
constraint required combining them into _cleanup() with an `(exit $rc)` to
preserve the outgoing exit code across the shred call for log_upload_and_exit's
`$?` capture.
