fix(zsh): setopt INTERACTIVE_COMMENTS in system-wide zshrc.d config

Recurring paste-copy pain during operator work: zsh's interactive shell
does NOT treat `#` as a comment character by default (unlike bash). Any
paste that includes `# comment` lines produces:

    zsh: command not found: #
    zsh: command not found: #

The `#` line is parsed as a command lookup, fails, and every subsequent
comment produces the same error. Doesn't break workflows (the actual
commands still run), just adds noise + occasional operator "did that
work?" confusion.

Same annoyance surfaced multiple times over the last several days of
migration testing (each block of copy-paste from the assistant included
`# Phase N` headers etc.). Fix once, done.
