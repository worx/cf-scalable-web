### 18:21:53 - Response

Two useful findings:

**URI pattern**: `s3://2025-09/branding.pdf` — the s3fs convention where `2025-09/branding.pdf` is the object key. The BUCKET NAME lives in module config, not the URI. So Drupal expects `s3fs.settings.bucket = <something>`.

**The jq error** is the diagnostic derailing: the secret is plain text, not JSON. Fix + retry:

```bash
cd /var/www/drupal
source /etc/worxco/envs/sandbox
export DRUPAL_DB_PASS=$(aws secretsmanager get-secret-value \
  --secret-id worxco/sandbox/drupal/db-password \
  --query SecretString --output text)
sudo -E HOME=/root vendor/bin/drush pm:list --status=enabled 2>&1 \
  | grep -iE 's3|amazon|flysystem|storage'
```

**Alternative simpler diagnostic** — look at the code directly:

```bash
ls /var/www/drupal/web/modules/contrib/ 2>/dev/null | grep -iE 's3|amazon|flysystem'

# See if s3fs is in composer.json
grep -iE 's3|amazon|flysystem' /var/www/drupal/composer.json 2>/dev/null
```
