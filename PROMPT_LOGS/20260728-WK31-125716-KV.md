## What's actually happening

That URL isn't an S3 URL at all — it's a Drupal *route*. Chain of Drupal internals when you hit `/admin/zoning-info/reports/conformance-reports/92284`:

1. Drupal router → matches a route in a custom module
2. Controller loads entity #92284 from the **database**
3. Entity references a file → `file_managed` table row → URI like `s3://YYYY-MM/whatever.pdf`
4. Drupal calls the stream wrapper for `s3://` → **flysystem_s3** resolves it → serves from sandbox bucket

**Steps 1-3 are database-driven. Step 4 is what we just wired.**

Your current sandbox DB is the *pre-migration* sandbox — it doesn't have entity 92284. That entity is a **prod** entity that only arrives when you run the DB migration (per `zesty-plotting-squid`).

So the failure isn't S3 wiring — it's that the entity doesn't exist yet in this database. Either a 404 (if the route matches but entity is missing) or WSOD (if the route needs the entity to build the page). Which was it? Would help confirm my read.
