feat(deploy): publish DNS early in deploy-all + SOA MIN preflight

Per Kurt 2026-07-31: DNS resolution shouldn't be the bottleneck after
a fresh sandbox rebuild. Front-load publish-dns to run the moment
the ALB is up, so by the time install-drupal + migrate-full-all finish
(1-2 hours later), any DNS negative-cache from BEFORE the record
existed has long expired.

## Three pieces

### 1. New `dns` track in deploy-all-parallel.py

    "dns": {"deps": ["alb"], "label": "dns",
            "name": "Route 53 alias + SOA preflight",
            "cmd": "make publish-dns ENV={env}"}

Runs as soon as `alb` completes (typically ~15 min into deploy-all).
The `cnx` / `cph` compute tracks that depend on ALB take much longer,
so DNS gets published well before those finish.

Added to DISPLAY_ORDER after `nlb`, before `cnx`.

### 2. New scripts/publish-dns-soa-preflight.sh

Called by the `publish-dns` Makefile target. Idempotent SOA MINIMUM
check + UPSERT to 300 seconds if the zone's SOA MIN is higher.

  - Discovers zone via same logic as publish-dns.sh (SSM site-name →
    drop leftmost label → find hosted zone matching)
  - Reads current SOA, parses last field (MINIMUM)
  - If MIN > 300: UPSERT new SOA with MIN=300, serial+=1, other fields
    preserved
  - If MIN ≤ 300: no-op with success message
  - If ENV=production: SKIPS entirely per policy

Why 300s: aligns negative-cache TTL with the record's own ~5-min TTL.
Route 53's default 86400 (24h) caused a real-world stuck-for-hours
outage tonight — a resolver got NXDOMAIN before publish-dns ran and
cached it for 24h even after the record was created.

Why skip production: Kurt's explicit policy 2026-07-31. Production
records never disappear (no destroy-all cycles), so negative-cache
TTL is functionally irrelevant there. Change the SOA policy for
production explicitly if needed; automation won't touch it.

### 3. `publish-dns` Makefile target invokes the preflight first

Preflight runs unconditionally; the script itself decides whether
to act based on ENV. Any preflight hiccup logs a warning but does
NOT block the alias UPSERT (belt-and-suspenders — publish-dns has
to work even if the preflight has a network burp).
