### 13:26:10 - Response

Found it. The module IS enabled — but Drupal's compiled container doesn't have the `s3` stream wrapper registered. That's classic "settings.php changed but container is cached" behavior. The container's stream wrapper registrations were compiled at some earlier point *before* we injected the `$settings['flysystem']` block, and Drupal's still serving from that stale container.

## Fix — rebuild the container

```bash
cd /var/www/drupal
source /etc/worxco/envs/sandbox
sudo -E HOME=/root vendor/bin/drush cache:rebuild
```

Cache rebuild recompiles the DI container from current settings.php + config. The flysystem_s3 module will re-run its scheme-registration and pick up the `s3` config from our injected block.

## Verify — should now show `s3` in the list

```bash
sudo -E HOME=/root vendor/bin/drush php:eval \
  'print_r(array_keys(\Drupal::service("stream_wrapper_manager")->getWrappers()));'
```

Expected new output:
```
Array
(
    [0] => assets
    [1] => public
    [2] => temporary
    [3] => module
    [4] => theme
    [5] => private
    [6] => s3         ← new
)
```

## If `s3` still isn't in the list after rebuild

Then Drupal isn't seeing `$settings['flysystem']` at all. Sanity check:

```bash
sudo -E HOME=/root vendor/bin/drush php:eval \
  'var_export(\Drupal\Core\Site\Settings::get("flysystem"));'
```

Expected:
```php
array (
  's3' => array (
    'driver' => 's3',
    'config' => array (
      'region' => 'us-east-1',
      'bucket' => 'sandbox-drupal-media-kv-worxco',
    ),
    'cache' => true,
  ),
)
```

If that returns `NULL` — settings.php isn't being read (or drush is somehow looking at the wrong one). If it returns the array — the module has the config but is failing to register the wrapper for some other reason (a bad config value, a missing dependency, etc.) and we look deeper.

But 90% odds `drush cache:rebuild` fixes it. Try that first, refresh the report page in Safari, and see what happens.

## Nginx caches too

There's a chance nginx/opcache also has a stale response. If Safari still shows the error after cache:rebuild + a hard-reload (Cmd+Shift+R), try:

```bash
# Optional — restart PHP-FPM on both instances to bust opcache:

```
