migrate-full-all's AUTO=yes preflight fallback (Phase -1) calls

    chown: changing ownership of '/var/www/drupal-private/salt.txt':

    make[2]: *** [Makefile:1033: install-drupal] Error 1

    manual intervention.

Kurt fired migrate-full-all from an ubuntu shell on the deploy-host.
No sudo in the ubuntu → make → install-drupal chain, so the chown
failed at line 391 of install-drupal.sh.

## Fix

Change `install-drupal` Makefile target to invoke the script via
`sudo -E bash`. `-E` preserves the caller's env (ENV, AWS_*, PATH,
HOME) so passing ENV=sandbox etc. still works. Passwordless sudo is
standard on the deploy-host AMI per bootstrap.sh setup.

Works idempotently whether the operator ran `make install-drupal`
directly (as ubuntu, needs the auto-sudo) or `sudo make
install-drupal` (already root, sudo is a no-op).

Also enables `make migrate-full-all AUTO=yes` to complete Phase -1
without operator intervention — which was the whole point of AUTO=yes.
