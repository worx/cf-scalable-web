```bash
  echo "=== FULL TEST CYCLE PASSED ==="
} 2>&1 | tee /tmp/full-test-$(date +%Y%m%d-%H%M%S).log
```

**What each change does:**

- **`deploy-migrate-host`** — deploys the ephemeral r7g.xlarge migrate-host + Phase 1 auto-restore-from-S3 pulls back your history/dotfiles. ~5-6 min. Runs from wherever you're driving the chain from (Mac or deploy-host, both work).
- **`HOST_STACK=cf-migrate-host`** — env var (no `;` — must be prefix to `make`) that tells `_ssm-run-deploy-host.sh` to dispatch to migrate-host instead of the deploy-host default. Propagates cleanly through the boosted wrapper's shell → child `make` → dispatch script.
- **`migrate-full-all-boosted`** — wraps the whole migration in RDS boost (db.t4g.micro → db.r7g.xlarge, ~5 min upfront) + revert-on-exit trap (fires even if migration fails — RDS never orphaned at expensive tier).
- **`destroy-migrate-host CONFIRMED=yes`** — auto-backup fires (state preserved in S3 for next deploy), then teardown. `CONFIRMED=yes` skips the interactive prompt.

**Two things you're not missing but worth flagging:**

1. **Your `compute-php-sandbox.json` change (EnablePHP74=false) must be present on whichever host runs the chain.** The `PHP74_ENABLED` Make macro reads that file at parse time. If you run from a host where the JSON is still `"true"` (my commit deliberately didn't stage your working-tree change), PHP74 gets built. Either commit + pull first, or run from your Mac where the change already exists locally.

2. **On failure, migrate-host stays up.** The chain's `&&` short-circuit means if the migration or smoke test fails, `destroy-migrate-host` doesn't run. That's actually desirable — leaves evidence for debugging. Just remember to `make destroy-migrate-host` manually if a step fails.
