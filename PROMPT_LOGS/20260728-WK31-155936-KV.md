docs: clarify mixed secret-storage convention + capture research-document bundle gaps

Two loose-end fixes from last night's S3 migration debugging.

## 1. `docs/ARCHITECTURE.md` — mixed secret-storage convention

The `Always Use Secrets Manager` example showed:

    ... --query SecretString --output text | jq -r .password

but *most* secrets in this project (Drupal DB password, hash salt) are
stored as raw strings, not JSON. Piping raw-string secrets through
`jq -r .password` silently returns empty — which is exactly how I got
bitten twice this week, once when running drush from the deploy-host
and once in the sandbox test-migration runbook.

Fix: rewrote the example to use the raw-string retrieval (`--output
text` alone). Added a small table documenting the mixed convention:

| Secret pattern | Storage format | Retrieval |
|---|---|---|
| `worxco/<env>/drupal/db-password` | Raw string | `--output text` (no jq) |
| `worxco/<env>/drupal/hash-salt`   | Raw string | `--output text` (no jq) |
| `cf-migration/prod-mysql-*`       | JSON | `--output text \| jq -r .password` |

The `cf-migration/prod-mysql-*` secret genuinely IS JSON (see the
schema comment in `migration/cloudformation/cf-migration-secret.yaml`),
so `jq -r .password` there is correct — no change to that file.

## 2. `docs/memory/research-document-bundle-gaps.md` (new)

Documents the finding that 4 of 12 `zi_research_document` bundles
(`variance`, `special_use_permit`, `planned_unit_development`,
`conditional_use_permit`) have no PHP bundle-class subclass file.
The `bca` module instantiates the base `ResearchDocument` for these,
which doesn't define `getResearchAnswer()` — any call site that
invokes it without a `method_exists` guard crashes when the DB
references one of the four permit-type bundles.

Includes:
- Explicit lists of which bundles have subclasses and which don't

  `ConformanceAnalysisTrait.php:86` — call without guard;

     `method_exists` guard pattern?

     documents that aren't binary yes/no like violations?

Kurt intends to raise these with Zac directly; the memory file gives
a durable pointer future sessions can reference.
