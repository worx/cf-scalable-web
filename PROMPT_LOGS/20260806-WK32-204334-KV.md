### 20:44:31 - Response

Two things to unpack. First, the warm-up theory doesn't fit this evidence — `smoke-test-drupal` uses `curl --resolve` to bypass DNS entirely and hit the ALB IP directly (see Makefile:3094 comment: "DNS lookup is bypassed"). So DNS isn't part of the failure path here. The Host header IS `sandbox.envs.zoning-info.com` (Drupal needs it in `trusted_host_patterns`), but Route 53 isn't consulted.

Second — and more importantly — install-drupal is supposed to leave you with a *working* base Drupal at that URL from day one. Migration later swaps the CONTENT, not the URL. A fresh drush site:install (even before any migration) should return HTTP 200 on `/` (the anonymous login page or a "Welcome to Drupal" page). It should NOT redirect to `/core/install.php`.

The 302 to `/core/install.php` is Drupal's bootstrap saying: "I looked at the DB, didn't find the install-complete marker, so I'm sending you to the installer." So install partially ran (drupal_user exists, 54 tables), but the "install completed" flag never got set. Which means drush site:install died mid-way and install-drupal.sh masked its exit code.

54 tables is suspicious — a completed drush site:install (even minimal profile) usually lands 60-90+ tables. This looks like partial install.

Two targeted checks that'll pin it down in 10 seconds:

```bash
# 1. Is the install-complete marker present?
psql-env sandbox -c "SELECT name FROM public.config 
                      WHERE name IN ('system.site','core.extension','system.site.uuid') 
                      ORDER BY name;"
# Expect: system.site, core.extension both present on a complete install.
# If missing → drush died before finalizing config.

# 2. Where did the install actually die? Look for drush errors in the log.
grep -iE 'error|fail|exception|\[warning\]' /var/log/worxco-migration/install-drupal-remote-20260807-013254Z.log | tail -30
```

The log grep will tell us *what* drush choked on. My guess is either a module install failure (something in the profile's required modules), a settings.php write-then-clobber, or a permissions issue on the file mount. Paste the outputs.
