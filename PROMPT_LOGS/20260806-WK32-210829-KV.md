### 21:08:43 - Response

That variability with all 4 cores lighting up is exactly what a healthy concurrency=4 run looks like. pgloader alternates between MySQL-read (I/O-bound, CPU dips) and Postgres-write (bursty CPU during batching + index builds), so you'll see the pattern: brief 100% spike during a batch flush or index build, drop to 0-30% while the next batch of rows streams over from MariaDB, spike again.

The tell that concurrency=4 isn't working would be 1 core pinned + 3 idle. Four cores all cycling = 4 tables in flight simultaneously. Phase 2's biggest bet is being validated in real time.
