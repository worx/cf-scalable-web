## Immediate fix — get the site serving

Edit sandbox settings.php on FSx:

```bash
make ssm-deploy-host
sudo use-env sandbox

# Look up the bucket name from SSM (or just hardcode — same result)
BUCKET=$(aws ssm get-parameter --name /sandbox/s3/media-bucket \
  --query 'Parameter.Value' --output text)
echo "Bucket: $BUCKET"

# Back up settings.php before edit
sudo cp /var/www/drupal/web/sites/default/settings.php \
        /var/www/drupal/web/sites/default/settings.php.pre-flysystem-$(date -u +%Y%m%d_%H%M%SZ)

# Append the flysystem config block
sudo tee -a /var/www/drupal/web/sites/default/settings.php > /dev/null <<PHP

# ============================================================
# flysystem s3:// scheme (added 2026-07-19 for prod-migration test)
# Sandbox's own drupal-media bucket. Sandbox compute has an IAM
# instance-role granting S3 access to this bucket — no static keys
# needed here. Prod would use its own bucket name.
# ============================================================
\$settings['flysystem'] = [
  's3' => [
    'driver' => 's3',
    'config' => [
      'region' => getenv('AWS_DEFAULT_REGION') ?: 'us-east-1',
      'bucket' => getenv('DRUPAL_MEDIA_BUCKET') ?: '$BUCKET',
      'prefix' => '',
    ],
    'cache' => TRUE,
  ],
];
PHP

# Preserve ownership + perms
sudo chown root:www-data /var/www/drupal/web/sites/default/settings.php
sudo chmod 0640 /var/www/drupal/web/sites/default/settings.php
exit

# Clear the compiled container so Drupal re-reads settings.php:
make clear-drupal-cache ENV=sandbox
```

## Diagnosis of the WSOD

The site errored because `file_managed` rows reference `s3://` URIs but the stream wrapper wasn't registered. When Drupal tried to build any page/entity that touched those references, it threw "unhandled scheme" or similar deep in the file entity render. That's your unexpected error. Registering the scheme by adding flysystem config fixes it.
