```
fix(migrate-host): preflight for missing VPC exports + auto-cleanup ROLLBACK_COMPLETE

First `make deploy-migrate-host` attempt failed with:
  "No export named sandbox-vpc-id found. Rollback requested by user."

The migrate-host template imports sandbox-vpc-id + sandbox-public-subnets
+ sandbox-rds-sg-id from the project VPC stack. If cf-scalable-web-
sandbox-vpc isn't deployed, those imports fail and CFN rolls the
migrate-host stack back — leaving it in ROLLBACK_COMPLETE, which CFN
refuses to update, forcing the operator to manually delete before retry.

Two-part fix:

1. `.migrate-host-vpc-preflight` runs BEFORE `aws cloudformation deploy`.
   Uses `list-exports` to check all three required export names exist.
   If any are missing, prints an actionable message listing the minimum
   `make deploy-*` targets needed (or full deploy-all) and exits 1.
   Fails fast, no half-created stack.

2. `.migrate-host-rollback-cleanup` runs at the very top of
   deploy-migrate-host. If cf-migrate-host is already in
   ROLLBACK_COMPLETE (from a prior failed attempt), auto-delete it +
   wait for stack-delete-complete before proceeding. Only fires on
   ROLLBACK_COMPLETE — any other status (CREATE_COMPLETE, UPDATE_IN_PROGRESS,
   etc.) is left alone.

Both preflights are cheap (< 2 sec each). Order:
  backups-preflight → vpc-preflight → rollback-cleanup → CFN deploy
```
