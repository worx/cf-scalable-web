### 20:32:10 - Response

**`install-drupal-full ENV=sandbox`** — that's the right one for your goal.

Here's the ladder:
- `install-drupal` — the actual install (drush site:install + publish vhost + reload nginx). Must be run ON the deploy-host — will fail from your Mac.
- `install-drupal-remote` — SSM-dispatches `install-drupal` to the deploy-host. Works from Mac, but skips DNS + smoke tests.
- **`install-drupal-full`** — the full monty: `install-drupal-remote` + `smoke-test-drupal` (ALB DNS-bypass check) + `publish-dns` (Route 53 alias) + `smoke-test-public` (through-DNS check). ~5-7 min. Ends at "publicly reachable and end-to-end verified."

For "prove the whole system," `install-drupal-full` is exactly what you want — it also creates `drupal_user` in RDS (as a side effect of drush site:install) with the current secret's password, which is the specific thing we need for pgloader to auth. And the smoke tests will confirm ALB/nginx/PHP-FPM/Drupal are all wired end-to-end before you fire the migration.

So your revised sequence:

```bash
make deploy-migrate-host      # (running)
make install-drupal-full ENV=sandbox   # ← this one
psql-env sandbox -c "SELECT rolname FROM pg_roles WHERE rolname='drupal_user';"  # sanity check
time HOST_STACK=cf-migrate-host CONFIRMED=yes make dispatch-restore-mysql
time HOST_STACK=cf-migrate-host CONFIRMED=yes make dispatch-run-pgloader
```
