## Your insight — I 100% agree

**Add the purge as a step in destroy-storage-s3 (Makefile), not as a Lambda custom resource in CFN.** Reasons your suggestion beats mine:

- **Same functional result** — bucket empty before CFN tries to delete it
- **No Lambda infrastructure to write, maintain, or debug** — no IAM role, no inline Python, no custom resource wiring
- **No CFN complexity added** — the template stays exactly as it is today
- **Trade-off you accept:** it only works via `make destroy-storage-s3` / `make destroy-all`. If someone deletes the stack via AWS console, they'd hit the versioning problem manually. But — nobody does that here; `make` is the standard path.

The Lambda pattern is the "portable across any deletion mechanism" solution. Your version is "our project's operational-path solution." For a project where all destroys go through `make`, yours is better — simpler, less overhead, no new infrastructure.

```bash
scripts/purge-versioned-bucket.sh BUCKET_NAME
# Uses AWS_PROFILE env var (destroy-all already sets this).
```

```makefile
destroy-storage-s3:

    @# Then the existing CFN delete-stack logic
```
