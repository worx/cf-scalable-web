1. **ALB is serving!** Direct curl (bypassing DNS via `--resolve`) got HTTP 404 in 65ms. That's Drupal responding — connection, TLS, nginx → PHP-FPM → Drupal all work. The 404 for `/` is a separate Drupal issue we'll dig into after DNS.

2. **The DNS problem is REAL and 24h-cached on this VPC.** Look at the AUTHORITY response:
   ```
   envs.zoning-info.com.  233  IN  SOA  ns-517.awsdns-00.net.  ...  1 7200 900 1209600 86400
   ```
   The last `86400` is SOA MINIMUM — the negative cache TTL Route 53 tells resolvers. **24 hours.**
   
   The deploy-host queried before publish-dns ran, got NODATA, and cached "no such record" for 24 hours. AWS VPC Resolver honors SOA MINIMUM. Local `resolvectl flush-caches` doesn't help — the CACHE that has the bad answer is on AWS's side, not on your instance.


Then **private/incognito Safari window** (WebKit maintains its own DNS cache). Your Mac's ISP resolver probably didn't cache the NXDOMAIN as long as AWS VPC Resolver did. Should work.
