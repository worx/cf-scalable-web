feat(migration): migrate-full-all now covers media sync + codebase restore

Wraps two previously-manual steps into migrate-full-all so a full
fresh-sandbox migration is genuinely one call.

## What changed

Added two phases:

**Phase 4: sync-s3-media** (prod media bucket → sandbox drupal-media
bucket, incremental — cross-account s3 sync via jumpbox). Was
previously a separate `make sync-s3-media` step the operator had to
remember.

**Phase 7: dispatch-restore-codebase** (S3 tarball → /var/www/drupal/
+ auto-discovered composer path-repository siblings; preserves the
sandbox's settings.php + .installed marker across the atomic swap).
Was previously a separate `make dispatch-restore-codebase` step, and
its docstring called it "unusual" — but for the migrate-full-all
use case (test the app against prod data + code), it IS the standard.

## SKIP_CODEBASE=yes opt-out

Restore-codebase carries an implicit "sandbox code == prod code" claim.
The docstring warned that most sandbox test cycles WANT sandbox to run
newer/diverged code from prod (test the changes not-yet-in-prod). For
that case, set `SKIP_CODEBASE=yes` and Phase 7 is skipped with a
clear log message.

## What deliberately NOT included

**`dump-all` is NOT auto-invoked.** Dumps are a deliberate operator
step — the timing (fresh vs. night-old vs. week-old) usually matters
for what's being tested. The target's docstring explicitly notes
this as a prereq. Kurt's call, 2026-07-30.

## Phase re-numbering

  Phase 6: clear-drupal-cache

Now:
  Phase 4: sync-s3-media                    (new)
  Phase 5: dispatch-restore-files
  Phase 6: dispatch-restore-private
  Phase 7: dispatch-restore-codebase        (new, unless SKIP_CODEBASE=yes)
  Phase 8: clear-drupal-cache

Existing environment variables (AUTO, SKIP_BACKUP, SKIP_PREFLIGHT,
POLL_TIMEOUT) unchanged.

## New sequence when your dump-all finishes

```bash
# Still from wherever you are (Mac or deploy-host):
cd migration
git pull    # if not on deploy-host that ran dump-all — you're fine there

```

That will:
1. Preflight → auto-install-drupal if needed (AUTO=yes)
2. DB backup + restore-mysql + pgloader + cache-clear
3. Sync media bucket from prod
4. Restore public files
5. Restore private files
6. Restore codebase + auto-discovered composer siblings
7. Final cache clear
