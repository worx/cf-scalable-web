## Complete From-Scratch Sandbox Migration

**11 phases, ~65-80 min end-to-end.** Parallelization where safe. Notes for each phase inline.

```bash
{
  # Phase 1: sandbox infrastructure (foreground, ~35-40 min)
  make deploy-all ENV=sandbox || exit 1

  # Phase 2: migrate-host + install-drupal + publish-dns (parallel fan-out, ~5-6 min max)
  make deploy-migrate-host &
  MIGRATE_PID=$!
  make install-drupal-remote ENV=sandbox && make publish-dns ENV=sandbox
  FG_STATUS=$?
  wait $MIGRATE_PID; MIGRATE_STATUS=$?
  [ $FG_STATUS -eq 0 ] || { echo "install-drupal/publish-dns failed"; exit 1; }
  [ $MIGRATE_STATUS -eq 0 ] || { echo "deploy-migrate-host failed"; exit 1; }

  # Phase 3: DB migration on migrate-host with RDS boost (~15-18 min)
  #          - boost --async runs concurrent with restore-mysql
  #          - wait-if-boosting gates pgloader on RDS ready
  #          - trap-revert restores RDS to db.t4g.micro on exit
  cd migration
  HOST_STACK=cf-migrate-host make migrate-db-all-boosted ENV=sandbox AUTO=yes || exit 1
  cd ..

  # Phase 4: destroy migrate-host early (saves $ during file syncs; auto-backup fires)
  make destroy-migrate-host CONFIRMED=yes

  # Phase 5-8: file / media / private / codebase restores (target deploy-host + S3, ~10-25 min)
  cd migration
  make sync-s3-media          CONFIRMED=yes || exit 1
  make dispatch-restore-codebase CONFIRMED=yes || exit 1
  make dispatch-restore-files    CONFIRMED=yes || exit 1
  make dispatch-restore-private  CONFIRMED=yes || exit 1
  cd ..

  # Phase 9: cache clear AFTER restore-codebase (Commerce + other prod modules now on FSx)
  make clear-drupal-cache ENV=sandbox || exit 1

  # Phase 10: OPcache flush so PHP-FPM re-reads the fresh module tree
  make restart-php-fpm ENV=sandbox || exit 1

  # Phase 11: verify — both DNS-bypassed and through-DNS
  make smoke-test-drupal ENV=sandbox && \
    make smoke-test-public ENV=sandbox && \
    echo "=== FULL TEST CYCLE PASSED ==="
} 2>&1 | tee /tmp/full-test-$(date +%Y%m%d-%H%M%S).log
```

## What's happening at each phase

| Phase | What runs where | Why the order |
|---|---|---|
| 1 | deploy-all → sandbox VPC/IAM/storage/DB/cache/AMIs/compute | Foundation for everything |
| 2 | migrate-host + install-drupal + publish-dns (parallel) | All three need Phase 1 but not each other |
| 3 | migrate-db-all-boosted → RDS boost + restore-mysql + pgloader + cache-clear + revert | Requires migrate-host (Phase 2) + drupal_user (install-drupal in Phase 2) |
| 4 | Destroy migrate-host | Its work is done; save $$ during longer Phase 5-8 |
| 5-8 | S3 sync + FSx file restores (deploy-host targets, serial) | Must come AFTER migration; must run BEFORE Phase 9 |
| 9 | clear-drupal-cache | Second time — first was in Phase 3 BEFORE codebase; this one is AFTER codebase brought new modules |
| 10 | restart-php-fpm | OPcache re-read of the fresh codebase |
| 11 | Two smoke tests | Confirm sandbox is fully browsable |
