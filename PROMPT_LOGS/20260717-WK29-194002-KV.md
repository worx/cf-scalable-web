## Design decisions

**backup=yes default, cleanup=no default** (per Kurt): the safety net
is on by default because surprise data loss is worse than surprise
clutter. `SKIP_BACKUP=yes` overrides for the "sandbox is already
empty, no state to preserve" case. Backup DB is NOT auto-dropped
on success — operator inspects then explicitly runs `delete-db-backup`.

**Non-interactive**: CONFIRMED=yes is injected into every dispatched
sub-target. An operator running migrate-db-all has already opted
into the full sequence — per-phase prompts would defeat the purpose.

**Fail-fast**: Make's default recipe behavior (stop on first non-zero
sub-target). If Phase 1 or 2 dies, Phase 3 doesn't run — Drupal stays
broken (which is actually fine because the backup from Phase 0 is
right there for rollback).

**Rollback pointer**: the safety-net backup DB name is printed
prominently at Phase 0 exit, followed by the exact command to
rollback from it. Operators don't have to hunt for it in logs.

## New pieces

- `scripts/dispatch-db-backup.sh` — Mac-side wrapper. Inline SSM
