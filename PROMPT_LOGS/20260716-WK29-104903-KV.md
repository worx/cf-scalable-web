## Claude Code permission modes

Four modes control how tool calls (edits, shell commands, etc.) get approved. Cycle through them with **Shift+Tab** at the prompt, or set at launch with `--permission-mode <mode>`.

### 1. Manual (default)
**What happens:** Every tool that isn't pre-allowed in your settings prompts you (Allow / Allow always / Deny).
**Blocked / prompted / allowed:** All non-allowlisted tools prompt.
**When to use:** Any real work — production repo, unfamiliar codebase, anything reversible-but-annoying (git push, DB writes). Safe default.
**Risk:** Lowest. You see every action before it happens.

### 2. Accept Edits
**What happens:** File-modifying tools (Edit, Write, NotebookEdit) auto-approve. Bash and other tools still prompt.
**Blocked / prompted / allowed:** Edits allowed silently; Bash / MCP / other tools still prompt.
**When to use:** Multi-file refactors, doc pushes, mass renames — when you trust the edits but still want to gate shell exec. Sweet spot for most of what we do.
**Risk:** Low. Files can churn but git protects you; shell still gated.

### 3. Plan Mode
**What happens:** Read-only. Claude can Read, Grep, spawn read-only agents, WebFetch — but **cannot** Edit, Write, or run destructive Bash. Ends only when Claude calls `ExitPlanMode` to present its plan for your approval; approval flips you back to Manual (or whatever mode you were in) and the plan executes.
**Blocked / prompted / allowed:** All writes/exec blocked; read tools allowed.
**When to use:** "Design first, act second." Great before nontrivial changes — get a plan, redirect if wrong, then execute knowing the shape is right. Also useful when you want Claude to explore without touching anything.
**Risk:** Zero writes possible. Pure exploration.

### 4. Bypass Permissions ("auto" / "yolo")
**What happens:** All tools auto-approve. No prompts, ever, until you switch out.
**Blocked / prompted / allowed:** Everything allowed.
**When to use:** Isolated sandbox (git worktree, throwaway VM, dev container), long automated tasks where prompting would stall you. Explicitly opt in — Claude Code won't put you here by accident.
**Risk:** Highest. Claude can `rm -rf`, `git push --force`, curl external endpoints, mutate cloud infra — all without asking. Match to a blast radius you're OK with.

## For your work here

You're almost always in **Manual** by default, and it's the right call — deploy-host / CFN / migration work is high blast-radius. **Plan Mode** is worth reaching for on questions like "how should we structure the pgloader wrapper" before I start writing files. **Accept Edits** speeds up bulk file work like the WK29 backup path expansion. **Bypass** would be reckless in this repo — skip it.
