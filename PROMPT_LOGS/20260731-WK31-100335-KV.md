### 10:04:13 - Response

Slight distinction from what I actually meant — worth clarifying because the two options have different tradeoffs:

## Option 1: `AUTO=yes` calls `install-drupal-full` instead of `install-drupal`

**Pros:** One-line fix in migrate-db-all's AUTO=yes path.
**Cons:** install-drupal-full does 6 steps. Steps 5 (publish-dns) and 6 (smoke-test-public) are now problematic:
- **publish-dns** would fire redundantly — the new `dns` track in deploy-all-parallel.py already handles it at ALB-up time. Duplicate work, no harm.
- **smoke-test-public** hits the URL via real DNS. If the DNS negative-cache hasn't cleared (unlikely with our SOA=300 change, but possible in weird timing), the smoke test fails and migrate-full-all aborts — even though Drupal is actually fine.

## Option 2: Fix `install-drupal` itself to leave a functioning site (my actual recommendation)

Restructure the semantics:
- **`install-drupal`** = install + publish-vhost + reload-nginx  → **leaves a functioning, reachable Drupal on the ALB.** No DNS, no smoke-tests. The MINIMUM viable install.
- **`install-drupal-full`** = install-drupal + publish-dns + smoke-tests → **the standalone convenience wrapper.** For operators who want the whole thing in one command.

Then `AUTO=yes` keeps calling `install-drupal` (as it does today) but gets a working site because the definition of "installed" now includes "reachable."

## Which is architecturally cleaner

**Option 2.** The idea being: `install-drupal` shouldn't leave the environment in an unusable state. "Drupal is installed" should mean "Drupal will respond to requests on its intended endpoint." publish-vhost + reload-nginx are part of "installed" IMO — the drush install alone leaves broken infrastructure.

Option 1 works but layers convenience-wrapper semantics into the migration flow. Option 2 fixes the root ambiguity in what "install-drupal" means.

## Concurrent risk with Option 2

`install-drupal-full` currently does step 3 (reload-nginx) already. If we add reload-nginx to install-drupal, install-drupal-full would call reload-nginx TWICE (once via install-drupal, once directly). Fix: strip step 3 from install-drupal-full since install-drupal now covers it.

Small refactor. Worth doing if you agree with the semantic reshape. Or Option 1 (simpler, less clean) if you'd rather just move on.

**My vote: Option 2, do it now.** Which do you want?
