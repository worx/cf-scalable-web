Note upfront: `information_schema.tables.table_rows` is an **estimate** for InnoDB (from index stats), not exact. For quick eyeball comparisons it's fine; for exact counts you'd need `SELECT COUNT(*)` per table.

**All tables in `zinew`, biggest first:**

```sql
SELECT table_name,
       table_rows                                   AS approx_rows,
       ROUND((data_length + index_length)/1024/1024, 1) AS mb
FROM information_schema.tables
WHERE table_schema = 'zinew'
  AND table_type   = 'BASE TABLE'
ORDER BY (data_length + index_length) DESC;
```

**Cache tables only (matches bare `cache` AND `cache_*`):**

```sql
SELECT table_name,
       table_rows                                   AS approx_rows,
       ROUND((data_length + index_length)/1024/1024, 1) AS mb
FROM information_schema.tables
WHERE table_schema = 'zinew'
  AND table_type   = 'BASE TABLE'
  AND (table_name = 'cache' OR table_name LIKE 'cache\_%')
ORDER BY (data_length + index_length) DESC;
```

The escaped `\_` matters — LIKE treats bare `_` as a single-char wildcard, so `'cache_%'` would also match a hypothetical `cachex_foo`. `'cache\_%'` forces literal underscore.

**If you want ACCURATE cache counts** (worth it since there are only ~20 cache tables), run this to generate the queries then paste them back:

```sql
SELECT CONCAT('SELECT ''', table_name, ''' AS t, COUNT(*) AS n FROM `', table_name, '` UNION ALL')
FROM information_schema.tables
WHERE table_schema = 'zinew'
  AND (table_name = 'cache' OR table_name LIKE 'cache\_%')
ORDER BY table_name;
```

Trim the trailing `UNION ALL` off the last row, prefix with `USE zinew;`, and run. That'll give you exact counts.
