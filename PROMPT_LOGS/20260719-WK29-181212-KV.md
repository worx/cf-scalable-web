## Diagnostic first — let's see what Drupal actually points at

Before we commit to a path, run these on deploy-host to characterize the problem:

```bash
make ssm-deploy-host
sudo use-env sandbox

# 1. What S3 module is installed + what bucket is it pointing at?
psql-env sandbox -d drupal -c \
  "SELECT name FROM zinew.config

   ORDER BY name;"

# 2. For the likely candidates, see the config values
psql-env sandbox -d drupal -c \
  "SELECT name, LEFT(convert_from(data, 'UTF8'), 500) AS data_preview
   FROM zinew.config
   WHERE name IN ('s3fs.settings', 'flysystem.settings')
   ORDER BY name;"

# 3. How many file_managed rows point where?
psql-env sandbox -d drupal -c \
  "SELECT
     CASE
       WHEN uri LIKE 'public://%'  THEN 'public://'
       WHEN uri LIKE 'private://%' THEN 'private://'
       WHEN uri LIKE 's3://%'      THEN 's3://'
       ELSE 'other'
     END AS scheme,
     COUNT(*) AS n
   FROM zinew.file_managed
   GROUP BY 1
   ORDER BY n DESC;"

# 4. Sample s3:// URIs (if any)
psql-env sandbox -d drupal -c \
  "SELECT uri FROM zinew.file_managed WHERE uri LIKE 's3://%' LIMIT 5;"
```

## Path A — config-only fix (no data copy, PDFs will still 404)

If it's a config-only rewrite:
```sql
UPDATE zinew.config
SET data = replace(convert_from(data,'UTF8'), 'prod-bucket-name', 'sandbox-drupal-media-kv-worxco')::bytea
WHERE name = 's3fs.settings';
```
Plus `drush cr`. Config now points at sandbox's bucket, but the bucket is empty → PDFs still 404. Correct URL structure, no functional PDFs. Fine for testing "does Drupal boot / does the migration structure hold" but not "do PDFs open."

## Path B — copy prod bucket → sandbox bucket + Path A (full parity)

```bash
# One-time from Mac (needs ZoningInfoAdmin for prod read, ZI-Sandbox for sandbox write):
aws --profile ZoningInfoAdmin s3 sync s3://<prod-bucket>/ s3://<sandbox-bucket>/ \
  --source-region <prod-region>
```

Cost: transfer size (depends on prod bucket volume). Doesn't grant sandbox ongoing prod access — one-time copy. This gives full parity.

## Path C — cross-account RO (you said no; skipping)

Bucket policy on prod's bucket granting sandbox account read. Fastest infrastructure change, but breaks the isolation you deliberately have.
