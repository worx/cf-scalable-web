feat(migration): parallelize RDS boost with restore-mysql + fix DUMP_LOCAL_PATH

Kurt's live test caught two issues stacked:

1. BUG (immediate crash): restore-mysql.sh defaulted DUMP_LOCAL_PATH to
   /var/www/mysql/zinew.sql — the FSx path only present on deploy-host.
   Fresh migrate-host has no /var/www; dump download crashed on mkdir.
   Phase 2's marker-guard covered the SQL bulk-load wrap but missed
   this path default. Marker-guarding it now, symmetric with the wrap:
     migrate-host  → /var/tmp/migration/zinew.sql (bootstrap creates dir)
     deploy-host   → /var/www/mysql/zinew.sql    (FSx-mounted, unchanged)
   Still fully overridable via caller's environment.

2. DESIGN GAP (Kurt's optimization idea): RDS boost's 5-min reboot was
   serialized against restore-mysql (also ~3-5 min), even though the
   two touch completely different systems (restore-mysql = migrate-host
   MariaDB; boost = sandbox RDS). Kurt: "they can run concurrently."

New choreography (parallelized):

  rds-migration-tuning.sh boost --async
    Submits modify-db-instance + saves pre-boost config to SSM, then
    RETURNS IMMEDIATELY without waiting for available. The caller can
    now start restore-mysql (or any other non-RDS work) while RDS is
    still rebooting.

  rds-migration-tuning.sh wait-if-boosting
    Idempotent gate: if the pre-migration-config SSM parameter exists,
    wait for RDS to reach 'available'. If not, silent no-op. Safe to
    call from any hook that requires RDS-ready.

Wiring:

  rds-boosted-migration.sh
    Now calls 'boost --async'. Restore-mysql phase runs concurrently
    with RDS reboot.

  migration/Makefile: dispatch-run-pgloader
    Prepends 'wait-if-boosting' to guarantee RDS is at boosted config
    before pgloader connects. Zero cost for non-boosted flows (single
    describe-db-instances call, then no-op).

Expected savings: 3-5 min per migration (the overlap between RDS
reboot and restore-mysql). Total flow on the critical path becomes
max(boost, restore-mysql) + pgloader + revert instead of
boost + restore-mysql + pgloader + revert.

Files Modified:
- scripts/rds-migration-tuning.sh    (--async flag + wait-if-boosting cmd)
- scripts/rds-boosted-migration.sh   (call boost --async)
- migration/scripts/deploy-host/restore-mysql.sh (marker-guard DUMP_LOCAL_PATH)
- migration/Makefile                 (prepend wait-if-boosting to dispatch-run-pgloader)

Verified: bash -n on all three scripts, wait-if-boosting no-op returns
0 when no SSM param exists (dry-run against live sandbox).
