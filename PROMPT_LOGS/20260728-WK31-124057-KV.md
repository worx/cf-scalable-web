### 12:41:27 - Response

Ah — my bad. `/proc/$PID/environ` shows what the process was **launched with** (the initial exec-time environment on the process stack), not what's been added via `putenv()` at runtime. PHP-FPM's `env[…]` directives are applied via `putenv()` when the worker processes the pool config — so `getenv()` returns them, but `/proc/PID/environ` stays whatever the kernel captured at fork/exec time. That test was structurally invalid for FPM. Not your setup — my diagnostic choice.

Also, PHP-FPM defaults to `clean_env = yes`, which explicitly wipes the inherited environment before applying `env[…]` — that's why `/proc/environ` came back empty (or nearly so).
